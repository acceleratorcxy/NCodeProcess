# NC 处理报告查看器用户手册

> 适用程序：NCodeProcessReportViewer 1.0.0。  
> 本手册可公开发布，示例目录均为通用内容。

## 1. 程序用途

NCodeProcessReportViewer 用于只读查看 NCodeProcess 生成的 JSON 报告。它可以查看处理汇总、文件状态、APT 信息、参数统计、校验问题、F 结构证据、修改差异、运行日志和原始 JSON。

查看器不会修改 NC 程序或报告文件，也不会重新判断校验结果。

## 2. 部署与启动

推荐方式：

1. 将 `NCodeProcessReportViewer.exe` 放到 NC 处理目录；
2. 确认报告位于当前目录或 `NCodeProcessData`；
3. 双击 EXE。

查看器自动识别：

- `ncodeprocess-report-*.json`；
- 旧版 `ncpostprocess-report-*.json`；
- 当前目录、`NCodeProcessData`、旧版 `NCPostProcessData`。

也可以点击“打开报告文件”，直接选择其他目录的 JSON。

## 3. 界面布局

左侧：

- 报告列表：按修改时间倒序；
- 程序列表：全部程序、单个程序和未配对文件。

右侧八个页面：

1. 概览与可视化；
2. 文件明细；
3. APT 信息；
4. 参数统计；
5. 校验问题；
6. 修改与差异；
7. 运行日志；
8. 原始 JSON。

选择报告、程序或文件后，相关页面立即刷新。表格内容被截断时，把鼠标停留在单元格约 1.5 秒即可查看全文。

## 4. 查看报告

### 4.1 选择报告

点击左侧报告。加载时顶部显示状态；报告超过 5MB 时会提示“大报告，加载中”。当前版本加载期间界面可能短暂等待，这是已知限制。

### 4.2 选择程序和文件

- “全部程序”：显示报告全局内容；
- 选择程序：只显示该程序相关文件；
- “未配对文件”：查看未能归入程序的项目；
- 文件明细中选择单个文件：APT、统计、问题和差异页切换到该文件。

## 5. 概览与可视化

概览显示：

- 成功、失败、跳过、移动、删除；
- 警告和错误数量；
- 输入/输出目录和处理时间；
- 工具版本、报告来源、结构版本；
- 备份目录、归档时间戳；
- 用户确认和扫描警告。

柱状图只用于快速比较数量。报告字段缺失或不是数字时按 0 绘制，避免旧报告或异常报告导致崩溃。

## 6. 文件明细

文件表显示源文件、目标文件、程序名、动作、编码、状态、程序名来源和问题摘要。

常见状态：

- success：执行成功；
- failed：执行失败；
- skipped/review：跳过或需要复核；
- moved/deleted：归档或删除；
- planned：报告可能来自预览或兼容版本，尚无执行状态。

查看器只显示报告记录，不能从这里重新执行处理。

## 7. APT 信息

选择“全部程序”时显示报告级摘要：

- 机床；
- 主轴转速；
- 备刀/装夹刀具；
- 操作列表；
- 刀具使用程序数；
- GOTO、圆弧和抬刀汇总。

选择单个文件时显示：

- 后处理表、CATIA APT 版本、生成时间、程序名；
- 操作级进给和主轴；
- 冷却液和刀具规格；
- XYZ 行程、GOTO 点数、圆弧、抬刀和退刀平面。

报告没有 APT 数据时显示空状态，不表示报告损坏。

## 8. 参数统计

参数表显示每个文件的 F、S、X、Y、Z：

- 出现次数；
- 最小值；
- 最大值；
- G00 数量和是否发现。

统计来自主工具处理时的结果。查看器不会重新读取 NC 文件，因此即使原 NC 已被移动，报告仍可查看。

## 9. 校验问题

### 9.1 颜色和级别

- error：红色，通常表示该文件未安全写入或必须修正；
- warning：橙色，需要人工确认；
- info：普通提示或复核信息。

可以选择“全部”“error”“warning”筛选。

### 9.2 导出问题 CSV

点击“导出问题 CSV”，保存当前报告的全部问题。文件使用 UTF-8 BOM，可直接用常见表格软件打开。

导出 CSV 不会修改 JSON，也不会只导出当前筛选结果；它以报告中的完整问题清单为准。

## 10. F 异常与证据

页面会展开主工具写入的 F 识别结果，不会重新计算。

### 10.1 阶段

```text
move-in → plunge → approach → cut → retreat-near → retreat-clear → move-out
```

分别表示安全定位、主体下探、最后接近、切削、慢速离面、受控退刀和安全退刀/定位。

阶段由运动轨迹决定，不由 F 数值决定。退刀使用与 approach、plunge 或 move 相同的 F 可能是正常工艺。

### 10.2 精确/兼容结构组

- 精确结构组：运动结构和阶段高度一致，证据更强；
- 兼容结构组：同阶段结构可兼容，证据为中等；
- 样本数：独立显式 F episode 数，模态继承行不会重复计数。

### 10.3 离群

离群条目显示候选 F、参照 F、倍率、样本数、置信度、结构组和原始行。它表示“相对当前程序内重复结构明显偏离”，不是固定合法档位检查。

### 10.4 证据不足和覆盖率

- 未比较：没有足够稳定参照，不代表程序错误；
- 证据不足：同结构存在冲突，但不能可靠确定哪个值异常；
- 普通唯一结构只计覆盖率，不会逐行刷屏。

### 10.5 APT 状态

“在 APT”表示该 F 与报告记录的 APT `FEDRAT` 参考接近；“不在 APT”只表示没有匹配参考。APT 是辅助信息，不等于最终合法/非法结论。

## 11. 修改与差异

- 红色：删除；
- 绿色：新增；
- 蓝色/定位行：差异块位置或修改上下文；
- 修改说明：主工具记录的头部更新、M03、刀具、重命名等摘要。

差异来自报告，不要求当前目录仍保留原 NC 文件。

## 12. 运行日志

运行日志完整内嵌在 JSON 的 `runtime_log` 中。可以按事件类型筛选，并在下方查看完整详情，例如 traceback、扫描数量、备份结果和单文件处理摘要。

当前版本不生成独立磁盘日志，`log_path` 通常为空。看到“日志已内嵌本报告”属于正常状态。

## 13. 原始 JSON

原始 JSON 页面用于核对全部字段。文本只读。旧报告可能缺少 APT、F episode、配置快照或运行日志字段，查看器会使用兼容空值。

## 14. 常见问题

### 没有发现报告

点击“重新扫描报告”，确认文件名和目录符合规则，或直接点击“打开报告文件”。

### 报告读取失败

确认文件是完整 JSON，根节点是对象，`files` 是数组。不要用文本编辑器保存成截断或非 JSON 内容。

### 大报告加载时窗口短暂不响应

当前版本仍同步解析和渲染，加载提示并非后台任务。等待完成，不要连续点击多个报告。

### 数量与预期不同

查看“文件明细”和原始 JSON。汇总来自报告生成时的执行结果，不是查看器重新扫描当前目录得到的数量。

### APT/F 页面为空

旧报告或未配对 APT 的报告可能没有这些字段。这不影响文件、问题、差异和日志等其它内容。

### 报告中显示真实文件路径

路径来自报告本身。对外分享报告前应按组织要求脱敏；查看器不会自动修改或隐藏报告字段。

## 15. 安全与完整性

1. 查看器只读，不需要管理员权限。
2. 只打开可信来源的 JSON；超大或恶意构造文件可能占用较多内存。
3. 使用发布包内 `SHA256SUMS.txt` 核对 EXE。
4. 构建使用随机字节码加密密钥，同一源码的不同 EXE 哈希不同是正常现象。
