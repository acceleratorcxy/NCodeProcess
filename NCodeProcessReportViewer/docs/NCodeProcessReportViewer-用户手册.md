# 1. 产品概述

## 1.1 程序用途

NC 处理报告查看器用于解析 `NCodeProcess.exe` 导出的 JSON 处理报告，并以图表、表格和红绿色差异视图展示报告内容。

查看器与 NC 程序处理工具相互独立，可以单独复制和运行。查看器只负责阅读报告，不执行目录处理，不修改程序头，也不删除文件。

## 1.2 主要功能

- 自动扫描当前目录和 `NCodeProcessData` 文件夹中的报告。
- 支持手动打开其他位置的 JSON 报告。
- 展示成功、失败、跳过、移动、删除、警告和错误数量。
- 使用柱状图展示处理结果和校验问题。
- 按全部文件或单个文件查看 F、S、X、Y、Z 与 G00 统计。
- 红色突出错误、橙色突出警告。
- 红绿色高亮展示文件修改差异。
- 显示完整原始 JSON，便于核对或技术排查。

## 1.3 支持的报告

标准报告文件名为：

```text
ncodeprocess-report-YYYYMMDD_HHMMSS.json
```

报告根节点必须是 JSON 对象，且 `files` 字段应为文件记录数组。对于格式不正确或损坏的 JSON，程序会显示读取失败提示。

# 2. 使用前准备

## 2.1 系统要求

- Windows 7 或更高版本。
- 无需管理员权限。
- 无需安装 Python 或其他运行库。
- 建议屏幕分辨率为 1920×1080；默认窗口约 1290×720，不全屏，打开即可看全所有表头，支持缩放，最小尺寸为 1160×640。

## 2.2 推荐部署位置

将 `NCodeProcessReportViewer.exe` 放到包含 `NCodeProcessData` 文件夹的处理目录：

```text
处理目录\
├─ NCodeProcessReportViewer.exe
├─ 程序A.MPF
└─ NCodeProcessData\
   ├─ ncodeprocess-report-20260803_100000.json
   └─ ncodeprocess-report-20260803_110000.json
```

启动后，查看器会自动扫描：

1. EXE 所在目录。
2. EXE 所在目录下的 `NCodeProcessData` 子目录。

# 3. 快速开始

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | 将查看器 EXE 放入处理目录 | 可自动定位报告文件夹 |
| 2 | 双击启动 | 自动扫描报告列表 |
| 3 | 在左上选择报告 | 加载报告摘要和文件明细 |
| 4 | 在左下选择“全部文件”或单个程序 | 筛选右侧统计、问题和差异 |
| 5 | 切换右侧页面 | 查看图表、统计、问题、差异或原始 JSON |

如果自动扫描未找到报告，点击“打开报告文件”，手动选择 JSON。

# 4. 界面说明

## 4.1 顶部工具栏

| 控件 | 作用 |
|---|---|
| 打开报告文件 | 手动选择其他目录中的 JSON 报告 |
| 重新扫描报告 | 重新扫描当前目录及 NCodeProcessData |
| 当前报告 | 显示当前加载报告的完整路径 |

## 4.2 左侧报告列表

“报告列表”显示自动发现的报告文件，包括文件修改时间和报告文件名。默认按文件修改时间从新到旧排序，并自动加载最新报告。

## 4.3 左侧文件明细

加载报告后，下方显示：

- `全部文件`：汇总查看整份报告。
- 单个程序或文件：只查看该条文件记录。
- 动作或实际状态。
- 错误和警告数量。
- 目标路径（重命名/移动/归档后的位置）与程序名来源标记（MSG / PPRINT / 文件名 / 手动确认）。

存在错误的记录使用红色加粗文字，存在警告的记录使用橙色加粗文字。

表格中内容较长而被列宽截断的单元格，鼠标悬停约 1.5 秒后会自动弹出浮窗显示完整内容；移开鼠标或点击/滚动表格时浮窗自动隐藏。

## 4.4 右侧功能页面

| 页面 | 内容 |
|---|---|
| 概览与可视化 | 报告摘要、目录时间信息、工具版本/报告来源/处理耗时/归档时间戳/用户确认项/扫描警告、处理结果和问题柱状图 |
| 参数统计 | F、S、X、Y、Z 次数、最小值、最大值及 G00 数量 |
| 校验问题 | 文件、行号、级别、类型、原始文本和建议；页面下方展示 F 离群检测明细（APT 规划档位、常用档位、档位包络与离群/复核明细行，含原始文本） |
| 修改与差异 | 修改说明和红绿色 unified diff |
| 运行日志 | 本次处理的事件时间线（时间 / 级别 / 事件 / 消息），错误红、警告橙突出，可按事件类型筛选；日志完整内嵌报告，不再生成磁盘日志文件 |
| 原始 JSON | 报告完整原文 |

# 5. 查看报告概览

## 5.1 摘要指标

概览页顶部显示七项指标：

| 指标 | 含义 |
|---|---|
| 成功 | 成功生成或更新的 MPF 数量 |
| 失败 | 因错误、占用或写入异常而失败的文件数量 |
| 跳过 | 未执行实际处理的文件数量 |
| 移动 | 已移动或归档的 APTSOURCE 数量 |
| 删除 | 已删除的中间文件、未保存 APTSOURCE 或重复文件数量 |
| 警告 | 报告中所有 warning 级别问题数量 |
| 错误 | 报告中所有 error 级别问题数量 |

## 5.2 报告元数据

摘要卡片下方显示：

- 输入目录。
- 输出目录。
- 处理开始时间。
- 处理完成时间。
- 工具版本、报告来源（GUI/CLI）与报告结构版本（如报告包含）。
- 处理耗时与 APTSOURCE 归档时间戳（如报告包含）。
- 用户确认项与扫描警告（如报告包含）。

这些信息用于确认报告是否属于当前项目和本次处理批次。

## 5.3 柱状图

“文件处理结果”图展示成功、失败、跳过、移动和删除数量；“校验问题”图展示错误和警告数量。

图表用于快速判断处理批次是否存在明显异常，具体原因仍需在“校验问题”和“修改与差异”页面核对。

# 6. 按文件筛选报告内容

## 6.1 查看全部文件

选择“全部文件”后：

- 参数统计页显示报告中所有带统计信息的文件。
- 校验问题页显示所有文件的问题。
- 修改与差异页按文件顺序集中显示所有修改记录。

适合进行批次级总体检查。

## 6.2 查看单个文件

选择一个程序或文件后，右侧页面只显示该文件的统计、校验和差异信息。适合对红色或橙色异常记录进行逐项复核。

> [!TIP]
> 建议先在“全部文件”中查看总体错误数量，再从左侧选择异常程序进行详细检查。

# 7. 查看参数统计

## 7.1 参数列说明

| 列 | 含义 |
|---|---|
| 文件/程序 | 统计数据所属的源文件 |
| 参数 | F、S、X、Y、Z 或 G00 |
| 次数 | 参数在程序正文中的出现次数 |
| 最小值 | 该参数解析出的最小数值 |
| 最大值 | 该参数解析出的最大数值 |
| G00 | 是否发现 G00/G0，或对应数量状态 |

## 7.2 参数解释

- F：进给速度。
- S：主轴转速。
- X、Y、Z：机床坐标或运动参数。
- G00：快速定位指令数量。

最小值、最大值和次数用于发现行程异常、速度异常或程序内容明显缺失，但不能代替工艺人员和机床操作人员的最终审核。

## 7.3 空白值

某参数在程序中没有出现时，最小值和最大值可能为空。报告记录没有 `stats` 数据时，该文件不会产生参数统计行。

# 8. 查看校验问题

## 8.1 问题列说明

| 列 | 含义 |
|---|---|
| 文件 | 问题所属文件 |
| 行 | 原程序中的行号 |
| 级别 | error、warning 或 info |
| 类型 | 校验规则名称 |
| 原始文本 | 触发问题的程序行或相关内容 |
| 建议 | 推荐的人工检查或修正方法 |

## 8.2 颜色含义

- 红色加粗：错误，需要优先处理，可能导致对应文件处理失败。
- 橙色加粗：警告，需要人工确认，但不一定阻止处理。
- 普通文字：信息提示。

## 8.3 推荐处理流程

1. 优先查看 error 级别记录。
2. 根据文件名和行号定位源 MPF。
3. 阅读原始文本和建议。
4. 对 F0、异常低 F、多 S、G00 等关键问题进行工艺复核。
5. 修正源程序后，使用主程序重新扫描和处理。

# 9. 查看修改与差异

## 9.1 修改说明

每个文件先显示“修改：”记录，例如补全程序头、补写 M03、更新刀具信息或重命名文件。

## 9.2 差异颜色

| 显示方式 | 含义 |
|---|---|
| 绿色背景、`+` 开头 | 修改后新增的行 |
| 红色背景、`-` 开头 | 修改前删除或被替换的行 |
| 蓝色文字、`@@` | 差异所在行段的位置 |
| `---` / `+++` | 修改前和修改后的文件标识 |
| 普通文字 | 差异上下文中的未修改行 |

## 9.3 核对重点

- PROGRAM、图号和版次是否正确。
- NC MACHINE 和 CONTROL SYSTEM 是否符合机床。
- DATE 是否符合预期。
- 刀具 MSG 是否位于头部最后。
- M03 或 TnM6 是否插入到正确位置。
- 第一条 NC 正文前是否出现多余空行。
- 无关 NC 指令和格式是否保持不变。

# 10. 查看原始 JSON

“原始 JSON”页面显示当前报告的完整内容，并支持横向和纵向滚动。

该页面适用于：

- 核对界面显示是否与报告原文一致。
- 向技术支持提供完整报告结构。
- 查找界面未单独展示的运行状态或错误文本。
- 开发接口或进行自动化数据分析。

查看器不会允许在该页面编辑或保存 JSON。

# 11. 报告指标说明

## 11.1 文件动作与运行状态

报告中的 `action` 表示处理计划，`status` 表示实际执行结果。常见值包括：

| 值 | 说明 |
|---|---|
| keep | 保留或写入 MPF |
| move | 移动或归档 APTSOURCE |
| delete | 删除中间文件或未保存 APTSOURCE |
| duplicate | 与其他文件产生相同目标名称 |
| success | 文件处理成功 |
| failed | 文件处理失败 |
| skipped | 文件被跳过 |
| moved | 文件移动成功 |
| deleted | 文件删除成功 |
| duplicate-removed | 较旧重复文件已在最新文件成功后清理 |
| duplicate-retained | 最新文件未成功，较旧文件保留 |

## 11.2 报告保留数量

主程序默认只保留最新三份报告。因此需要长期归档的报告，应复制到项目档案目录或其他受控位置。

# 12. 常见问题与故障处理

| 现象 | 可能原因 | 处理方法 |
|---|---|---|
| 启动后显示未找到报告 | 当前目录和 NCodeProcessData 中没有标准报告 | 点击“打开报告文件”手动选择 |
| 报告读取失败 | JSON 损坏、编码异常或结构不符合要求 | 使用文本工具检查 JSON，重新从主程序导出 |
| 报告列表没有最新文件 | 文件刚复制或目录内容变化 | 点击“重新扫描报告” |
| 某文件没有参数统计 | 报告中该文件的 stats 为空 | 检查主程序是否成功解析或处理该文件 |
| 差异页面为空 | 文件没有变化或报告没有记录 diff | 属于正常情况，查看 action/status 确认 |
| 图表数量与文件行数不同 | 移动、删除、重复文件和 MPF 统计口径不同 | 结合摘要和文件明细核对 |
| 窗口内容显示不全 | 窗口过小或 Windows 显示缩放较高 | 调整窗口或系统缩放，使用滚动条 |
| 无法打开其他位置报告 | 文件无权限、被占用或路径失效 | 复制报告到可读目录后重试 |

## 12.1 报告本身没有问题但显示异常

1. 关闭查看器。
2. 将报告复制到本地普通目录。
3. 重新启动并使用“打开报告文件”。
4. 如仍失败，使用原始 JSON 页面或文本编辑器检查报告内容。

# 13. 附录

## 13.1 标准报告目录

```text
处理目录\
├─ NCodeProcess.exe
├─ NCodeProcessReportViewer.exe
└─ NCodeProcessData\
   ├─ special_tools.json
   ├─ ncodeprocess-report-20260803_100000.json
   └─ ncodeprocess-report-20260803_110000.json
```

## 13.2 用户检查清单

1. 当前报告路径属于正确项目。
2. 输入目录、输出目录和处理时间正确。
3. 失败和错误数量为零，或已逐项说明原因。
4. 所有警告已经人工确认。
5. F、S、X、Y、Z 范围符合机床和工艺要求。
6. G00 数量符合项目规范。
7. 关键程序的修改差异已经检查。
8. 重要报告已经复制到长期归档位置。

## 13.3 与主程序的关系

| 程序 | 主要职责 | 是否修改 NC 文件 |
|---|---|---|
| NCodeProcess.exe | 扫描、预览、校验、修改、归档、清理、导出报告 | 是，需用户二次确认 |
| NCodeProcessReportViewer.exe | 读取并可视化展示 JSON 报告 | 否，只读 |
