# Windows 7 响应式界面布局设计

## 背景与目标

NCodeProcess 在 Windows 7、1366×768、100% DPI 环境中存在固定宽度布局溢出：右侧按钮消失、图号候选框挤压“选取此项作为图号”按钮、程序选择表格校验列显示不完整、刀具表格和编辑器无法同时完整显示。目标是在不改变现有业务功能和操作顺序的前提下，使程序在最低支持分辨率下默认启动即可完整看到所有主要控件和表头，并在更大窗口中自动扩展。

最低支持环境为 Windows 7、1366×768、100% DPI。Windows 10/11、1600×900 和 1920×1080 应保持兼容。低于最低支持分辨率不承诺同时显示全部数据行，但窗口最小尺寸必须阻止控件被压缩到不可操作状态。

## 根因分析

1. 程序信息区域使用单个 14 列 `grid`。五个固定字符宽度输入框、多个复选框、宽度为 54 字符的图号候选框以及右侧按钮共享同一行列体系。Windows 7 主题、字体度量和控件边框比当前开发环境占用更多像素，导致总请求宽度超过窗口客户区。
2. 主内容区使用水平和垂直 `ttk.Panedwindow`，启动后再调用 `sashpos` 设置 50% 位置。控件完成尺寸计算前后的请求宽度变化会造成分隔条闪动，且任一子区域的固定请求宽度都可能把另一侧挤压。
3. 程序选择表格的主表固定列宽总计 635 像素，校验子表另占 85 像素，再加滚动条、Notebook 边框和主题内边距后，接近或超过 1366×768 下左半区的实际可用宽度。所有列均设置 `stretch=False`，无法吸收 Windows 7 的宽度差异。
4. 刀具表格固定列宽总计 485 像素，编辑器固定宽度 315 像素，二者连同滚动条和内边距超过右半区可用宽度，因此 TOOL_TYPE 表头或编辑按钮被截断。
5. 当前初始窗口在 1366×768 屏幕上使用 `screen_width - 160` 和至少 760 像素高度，未充分考虑 Windows 7 标题栏、任务栏和窗口边框占用。
6. `Treeview` 和修改差异页的两个 `Text` 控件保留 Tk 默认请求行数/字符宽度。即使父容器可以缩放，这些默认请求尺寸仍会把主内容区请求宽度推高。当前开发环境实测整个应用请求尺寸为 1947×914；主内容区请求宽度为 1931，其中右侧审查区请求宽度为 1179。

## 选定方案

采用方案 A“响应式分区布局”。保持现有功能分组和操作顺序，移除依赖启动后调整位置的主分隔条，改用明确的网格权重、最小宽度和可伸缩列。

## 窗口尺寸策略

- 初始宽度：在最低支持及更高分辨率使用 `min(1290, max(1180, screen_width - 80))`；低于最低支持分辨率时使用 `min(1600, max(900, screen_width - 40))`，避免窗口超出屏幕。
- 初始高度：在最低支持及更高分辨率使用 `min(720, max(650, screen_height - 100))`；更低屏幕使用 `min(900, max(560, screen_height - 60))`。
- 在 1920×1080 环境中，初始窗口约为 1290×720，不再几乎占满屏幕；所有表头在默认尺寸下直接可见。
- 最小客户区尺寸：最低支持环境为 1180×650；低于该环境时最小值随实际窗口尺寸降低，不承诺完整显示。
- 窗口居中且不最大化。
- 在 1366×768 环境中，初始窗口约为 1286×668，给 Windows 7 窗口边框和任务栏保留空间。
- 当实际屏幕小于最小支持环境时，窗口仍使用屏幕可容纳尺寸，但该环境不属于完整显示保证范围。

窗口尺寸计算应提取为无 Tk 依赖的纯函数，使其可通过单元测试验证。

## 顶部布局

顶部保持三个可见模块，但每个模块内部改为独立响应式容器：

1. 自动扫描目录行：目录标签区域配置权重并允许文本区域扩展；“重新扫描目录”“保存 APTSOURCE”和“包含子目录”保持固定请求宽度并靠右。
2. 程序基本信息行：编制、审核/校对、图号、版次、日期使用五个等权子区域。标签与输入框在各自子区域中排列，不再共享十四列全局网格。
3. 程序处理选项行：应用设置、保存编制/校对、覆盖字段、自动补写 M03、自动添加换刀指令、机床说明按独立区域排列。机床说明允许在空间不足时缩短显示为“机床：HASS/2500B；系统：SIE840D”，不影响实际数据。
4. 刀具类型与图号候选行：自定义刀具类型占左侧固定区域；图号候选区域使用三列结构——标签、可伸缩下拉框、固定按钮。下拉框不使用 54 字符固定宽度，只设置合理最小宽度并 `sticky="ew"`。按钮文本始终完整显示为“选取此项作为图号”。

顶部区域不添加整体滚动条。在最低支持分辨率中必须完整显示全部控件。

## 主内容布局

使用普通 `ttk.Frame` 作为主容器，配置两列等权重，替代水平 `ttk.Panedwindow`。左侧 Notebook 和右侧审查区各占约 50%，不再显示可拖拽分隔条，也不再需要启动后设置 sash 位置。

右侧使用两行等权重网格，第一行为解析/校验/统计/差异 Notebook，第二行为刀具信息区，替代垂直 `ttk.Panedwindow`。窗口高度变化时两部分同步扩展。

所有填充父容器的 `Treeview` 和 `Text` 控件设置较小的请求高度/宽度（例如 `height=1`、文本区 `width=1`），实际显示尺寸完全由父容器网格分配，避免默认请求尺寸反向撑大窗口。

该结构消除启动分隔条闪动，并避免用户拖动后长期处于控件被隐藏的状态。

## 程序选择表格

继续使用主 Treeview 与校验 Treeview 同步滚动的结构，以保留仅校验单元格标红加粗的需求。

最低布局列宽建议：

| 列 | 初始宽度 | 最小宽度 | 伸缩 |
|---|---:|---:|---|
| 动作 | 58 | 52 | 否 |
| 程序名 | 112 | 96 | 否 |
| MPF 源文件 | 205 | 130 | 是 |
| 目标 | 150 | 105 | 是 |
| 校验 | 82 | 78 | 否 |

主表的源文件和目标列共同吸收剩余宽度。默认窗口下所有表头和校验内容可见，底部横向滚动条处于无溢出状态；用户手动拉宽长文本列后，横向滚动条仍可正常工作。

APTSOURCE、待删除、解析信息、校验问题和参数统计表格继续保留横向滚动能力，但其默认列宽总和不得超过对应页面在最低窗口下的可用宽度。文本类列允许伸缩，序号、类型、级别等短列保持固定。

## 刀具信息与编辑器

刀具区使用两列网格：左侧表格权重为 1，右侧编辑器使用 230 像素最小宽度。编辑器不再通过 `pack_propagate(False)` 固定为 315 像素。

刀具表格列宽建议：

| 列 | 初始宽度 | 最小宽度 | 伸缩 |
|---|---:|---:|---|
| 刀具号 | 50 | 48 | 否 |
| DIA | 50 | 48 | 否 |
| TOOL_CONER | 82 | 76 | 是 |
| TOOL_ANGLE | 84 | 78 | 是 |
| TOOL_TYPE | 104 | 88 | 是 |

编辑器标签使用稳定的英文参数名，输入框随编辑器宽度扩展。新增/更新、删除、清除三个按钮按整行排列并始终完整可见。

## 布局辅助接口

在 `ncodeprocess.gui` 中新增不依赖 Tk 实例的布局计算函数：

- `window_geometry_for_screen(screen_width, screen_height)`：返回初始宽度、高度和最小宽高。
- `fit_column_widths(available_width, columns)`：根据初始宽度、最小宽度和伸缩标记压缩或扩展列宽，确保默认表头布局不溢出。

Tk 控件创建后通过 `<Configure>` 事件调用节流后的列宽更新逻辑。仅当容器宽度实际变化时重新计算，避免窗口拖动期间频繁抖动。程序选择表和刀具表分别使用自己的列配置。

## 错误处理与兼容性

- 若控件尚未完成布局、可用宽度小于 1 或控件已销毁，列宽更新直接返回，不抛出异常。
- Windows 7 不使用 `PanedWindow.add(minsize=...)` 等旧 Tk 不支持的参数。
- 不强制修改系统 DPI，不依赖 Windows 10/11 专属 API。
- 不更改扫描、解析、刀具编辑、报告导出和目录处理逻辑。
- 横向滚动条继续保留，用于用户主动拉宽列或遇到异常长标题；默认状态不依赖它查看表头。

## 测试策略

采用测试驱动开发：

1. 为 1366×768、1600×900、1920×1080 编写窗口尺寸测试，并先确认当前代码没有目标纯函数而失败。
2. 为列宽压缩编写测试，验证最小宽度、总宽度上限和固定列不被错误扩展。
3. 为列宽扩展编写测试，验证剩余空间只分配给可伸缩列。
4. 为程序选择表和刀具表的配置编写测试，验证在各自最低可用宽度下所有列宽总和不溢出。
5. 运行现有 35 项主程序测试，确认业务行为不变。
6. 使用 Python 3.8 启动界面进行 1366×768、1600×900 和 1920×1080 尺寸截图或控件几何信息验证。
7. 使用 PyInstaller 5.13.2 重新生成加固 EXE，并在 Windows 7 环境复测默认启动布局。

## 验收标准

- Windows 7、1366×768、100% DPI 默认启动时，全部顶部控件可见。
- 图号候选框右侧“选取此项作为图号”按钮完整可见。
- 程序选择表的动作、程序名、MPF 源文件、目标和校验表头完整可见；校验内容不被截掉。
- 刀具表格五个表头、编辑器五个字段以及三个操作按钮完整可见。
- 默认状态不需要拖动任何底部或侧边滚动条才能看全表头。
- 窗口在允许的最小尺寸以上缩放时不会隐藏控件；放大后各主要区域自动扩展。
- 主水平分隔条不再闪动。
- 所有现有业务测试通过，加固构建成功。
