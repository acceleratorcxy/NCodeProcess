# Windows 7 字体度量与表格可读性修订设计

## 背景与根因

Windows 7 实机使用与 Windows 11 不同的 Tk/系统字体度量和主题内边距。当前程序表格的 `校验=82px`、刀具编号=50px 等固定像素值是按 Windows 11 观察值设置的，在 Windows 7 上不足以容纳标题、校验摘要和系统主题留白；动态列宽虽然已经接入，但只按窗口宽度分配，没有把当前字体实际测量值作为最小宽度依据。顶部自定义刀具类型行的可伸缩列还把添加按钮推到了远端。

## 目标

- Windows 7 1366×768、100% DPI 下，校验摘要和“刀具号”表头完整显示。
- 程序名、MPF 源文件、目标列保持可辨识的列间间隔，不互相挤压。
- Windows 11 当前正常外观保持不变；不强制切换到 `clam` 等替代主题。
- 允许用户手动拉宽长文本列并继续使用水平滚动条。
- 自定义刀具类型输入框与“添加类型”按钮紧邻排列。

## 设计

1. 在保留原生 ttk 主题的前提下，选择可用的微软雅黑 UI/微软雅黑/Segoe UI/Tahoma 字体候选，并为 Tk 默认、正文、标题和 Treeview 样式设置一致的字体族与字号。若某字体在系统中不存在，按候选顺序回退。
2. 新增基于当前 Tk 字体 `measure()` 的列宽配置计算：校验列按“999 错 / 999 警”预留，刀具编号列按“刀具号”标题预留，其他列在现有 `KEEP_COLUMN_SPECS`/`TOOL_COLUMN_SPECS` 基础上按实际度量增补。固定列不会随窗口放大，伸缩列承接剩余空间。
3. 程序表和刀具表首次创建时使用最小安全宽度，映射后由现有 Configure/after_idle profile 分配实际宽度；左右主区域使用等权网格，避免 Windows 7 因请求尺寸差异导致左侧程序表被压窄。
4. 程序表的长文本单元格增加轻微显示间隔，不改变底层文件内容和业务数据；校验双表同步、红色粗体标签和水平滚动 wiring 保持不变。
5. 将 G00/自定义刀具类型行中的标签、输入框和按钮放进同一紧凑子区域，按钮紧邻输入框，不再让伸缩列吞掉中间空间。

## 验证

- 新增失败测试覆盖字体度量驱动的最小列宽、校验摘要、刀具号表头、程序表列间隔和自定义类型控件相邻性。
- 使用 Windows 7 风格字体/DPI 模拟探针，以及 1286×668、1600×900、1920×1080 三种窗口验证：所有关键表头和按钮在客户区内，固定列不随放大变化，伸缩列扩展，水平滚动可达末端。
- 全量 `conda run -n python38 python -m unittest discover -s tests -v` 通过后重新构建并核对发布包。
