## 一、确认的逻辑问题（Bug，建议优先修复）

### 1. M03 补写时 S 检测未排除注释，会把 M03 加错位置

- 位置：`core.py` `add_m03()` 的 S 转速循环（约 L764-L774）。
- 现象（实测）：正文 `N1G1X10 (FEED S5000 OK)`（S 只出现在括号注释里）经 `add_m03` 后输出：

  ```text
  N1G1X10 (FEED S5000 OK)M03
  ```

- 危害：程序实际没有有效 S 指令时，M03 被追加到注释行末尾；由于函数找到第一处即返回，后续真正需要补写 M03 的程序块不再处理。
- 需求依据：FR-05.4 要求针对"首个**有效** S 转速指令"补写。
- 不一致原因：同文件中 `calculate_stats`、`validate_program` 以及 `add_m03` 自己的 M03 检测循环均通过 `line.split("(")[0]` 剔除括号注释，唯独 S 检测循环直接对整行做正则，遗漏了注释剔除。

### 2. 无分号程序块的 M03 插入位置与需求不符

- 位置：`core.py` `add_m03()`（约 L772-L774）。
- 现象（实测）：无分号块

  ```text
  N1G0X0S2000F1000  →  N1G0X0S2000F1000M03   （加在块尾）
  ```

  带分号块 `N1G0X0S2000F1000;` → `N1G0X0S2000F1000M03;`（分号前，符合）。
- 需求依据：FR-05.4"默认紧跟在 S 数值之后；若该程序块带分号，则插入在分号之前"。无分号块应按约 `...S2000M03F1000` 处理，现实现统一加在块尾。

## 二、需求与实现不一致（需确认取舍）

### 3. M03 无法补写时仅警告而非错误

- 需求 FR-05.6：无法判断主轴方向/转速或不允许自动补写时，应标记为**错误**并要求用户确认。
- 实现：
  - `add_m03` 返回的"无法确定 M03 插入位置"提示在 `build_plan`（约 L1027-L1029）中未写入 `changes`，直接丢弃；
  - `validate_program` 仅产生 `spindle-start` **warning**（约 L918-L919）；
  - GUI 无 FR-07.4 要求的"错误确认放行"机制——存在错误的文件在 `process_plan` 中直接 `failed` 跳过，用户无法按文件放行。

### 4. 重复 MSG 字段未按"警告"上报

- 需求 FR-04.2.4：同一键出现多次时保留第一条，并将重复项报告为**警告**。
- 实现：`apply_header`（约 L655-L657）仅向 `changes` 追加文本"重复头部字段 …"，不进 `issues`，界面"校验问题"表中不可见，也不计入报告警告数。

### 5. 第 8 节配置要求大面积未进入 GUI

- 需求第 8 节："以下设置应在程序设置界面提供，并在当前运行期间生效"。
- 现状：GUI 仅暴露递归扫描、保存 APTSOURCE、覆盖非空 MSG、自动补写 M03、自动添加换刀指令、G00 级别、自定义刀具类型。
- 未提供界面（部分仅 CLI 有）：待删除扩展名白名单、程序名提取规则与允许字符、必填 MSG 字段、M03 补写策略细节、S/F 上下限、机床行程、结束标记/M06/辅助指令顺序规则、编码与换行策略。
- 其中 **FR-07.3"X/Y/Z 机床行程检查（未配置范围时提示'未执行行程检查'）"完全未实现**。

### 6. 需求文档自身矛盾（非代码错误，需澄清）

| 冲突点 | 需求 A | 需求 B | 实现遵循 |
|---|---|---|---|
| 自定义刀具类型存储位置 | 第 8 节：不得写入 NC 输出目录，保存到当前用户设置 | FR-03.8：特殊刀具存 `NCodeProcessData/special_tools.json` | FR-03.8 |
| TOOL_ANGLE 小数位 | FR-4.1 示例 `TOOL_ANGLE=-3.000000`（6 位） | FR-4.3.20：刀具数值统一三位小数 | 4.3.20（测试已锁定 3 位） |
| 未知扩展名处理 | FR-03.4：列入"待确认文件"清单 | 5.2：其他文件必须忽略 | 5.2（完全忽略） |

## 三、轻微偏差（可后续打磨）

- `apply_header`（约 L696-L697）会删除头部与正文之间已有的空行，与 FR-04.6"原文件已有格式空行按保留策略处理"存在张力。
- `extract_tools`（约 L592-L598）判定"普通立铣刀"仅比较 CUTTER/TOOLNO 直径，未比较圆角（FR-4.3.16 要求直径、圆角均一致）。
- FR-07.2"刀具调用是否包含对应刀具号""孤立的坐标/进给/转速指令"检查未实现（仅有地址无值检查 `invalid-address`）。
- FR-01.5"无 MPF 的目录应终止处理"：实现仅加 warning 不终止（但同条后半句允许纯 aptsource 目录继续归档/清理，属于需求内部条件性描述）。

## 四、合规确认（抽查通过）

- **程序名**：提取优先级（MSG PROGRAM / PPRINT PROGNAME → 末段下划线 → 整名）、`_I` 后缀与扩展名剔除、非法字符拦截、无法确定时要求人工确认；重命名与 APT 配对使用同一程序名。
- **重复目标**：按修改时间最新者覆盖；执行确认时逐项列出较旧文件/最新文件/目标文件；仅最新文件成功写入后才清理较旧源文件。
- **头部处理**：无目标 MSG 头默认 HASS 且 `%` 保留、MSG 插入 `%` 之后；有头部默认 2500B；CONTROL SYSTEM 缺省 SIE840D；PROGRAM / NC MACHINE / CONTROL SYSTEM / DATE 非空永不覆盖；PART VERSION 可在覆盖选项下修改；头部与正文之间不额外插入空行；保持原换行符与编码（自动识别，含 BOM）。
- **必填与提交**：图号、版次必填，未填或未点"应用"即报错放弃；目录名图号仅经"读取文件夹名作为图号"+"应用设置"后写入；图号候选按"MPF提取"/"APT提取"分来源各自合并、跨来源不合并；唯一图号自动预填。
- **刀具**：未选类型不输出 `TOOL_TYPE=`；子参数为空只省略；按刀具号排序、各占一行；Tn MSG 行始终位于程序头信息最后；APT 最新解析结果优先于 MPF 原 Tn 与 special_tools.json，再回退 special_tools 再回退 MPF；反锥/铅笔单边角 = 包含角/2；钻头/中心钻角度仅用于识别、不输出；`CUTTER/` 前两参作 DIA/TOOL_CONER；用户界面编辑值可参与本次预览。
- **M03（除问题 1、2 外）**：已有 M03/M3 不重复补写；MSG 文本不计为 M03；分号块插在分号前；补写记录进入 changes 并可在差异视图追溯。
- **统计**：F/S/X/Y/Z 出现次数、F/S 不同值列表、min/max；忽略 MSG、注释、空行、`%`；支持负数/小数/科学计数法；缺失显示"无数据"不误显 0。
- **校验**：F0 为错误；程序主 F 为千位时个位/两位数 F 给警告；多个不同 S 值给警告；G00/G0 默认错误、可配置为警告/允许；N 号重复/倒序警告；结束标记缺失错误；未闭合引号、控制字符、地址后无数值均报错；负 F/S 报错；必填 MSG 缺失报错；PROGRAM 与文件名不一致报错。
- **预览与处理**：扫描阶段只读不修改；取消确认不移动/不删除；处理按文件隔离异常、失败项集中报告；目标已存在且非覆盖/非胜出者时报错，不静默覆盖；临时文件原子替换。
- **报告**：默认不落盘；点击"导出报告"自动保存到 `NCodeProcessData`，文件名含时间戳，仅保留最新三份。
- **GUI 布局**：左右 50/50 网格无 PanedWindow；字体按 YaHei UI → YaHei → Segoe UI → Tahoma 选择；Treeview 9pt / 表头 8pt 粗体；列宽按实际字体 measure 计算；校验列按"999 错 / 999 警"预留；启动延后回调可安全取消；diff 双栏、红删绿增、3 行上下文、底部蓝色折叠汇总；刀具编辑区约 230px 且启动即可见。
- **偏好存储**：编制/审核保存到当前 Windows 用户注册表（`HKCU\Software\NCodeProcess`），兼容旧 `NCPostProcess` 键，不写配置文件到 NC 目录。
- **性能**：MPF 并行受控线程、统计与校验合并单次遍历、正则预编译、APT 仅读前缀/流式提取、未变化文件读取与刀具解析缓存。
