| 项目 | 内容 |
|---|---|
| 文档名称 | CATIA 后处理 NC 程序处理工具需求文档 |
| 文档版本 | V1.0 |
| 编写日期 | 2026-08-03 |
| 目标平台 | Windows 7（必须支持）的免安装便携式 Windows 程序，并可兼容后续 Windows 版本 |
| 文档状态 | 初稿 |

## 2. 项目背景

CATIA 后处理后通常会生成多个文件，例如 MPF、aptsource、LOG、MOAPTIndexes 和批处理文件。其中，实际交付和数控加工主要需要 MPF 文件；aptsource 文件是否留档由用户决定，默认不保存，其余文件一般属于中间文件或无用文件。

不同后处理程序生成的 MPF 文件格式也存在差异：

- **V5-2500B**：MPF 文件头部通常已经包含 `MSG("KEY:VALUE")` 格式的信息，但部分字段为空；文件中可能缺少 `M03`。
- **HASS**：MPF 文件头部通常没有项目要求的程序信息，需要工具自动补写；程序指令一般带有分号，且可能已经包含 `M03`。

本工具用于批量整理文件、规范程序名称、补全程序头部、检查 NC 指令并输出参数统计结果。

## 3. 项目目标

1. 批量处理 CATIA 后处理输出目录。
2. 保留并规范 MPF 文件。
3. aptsource 默认不保存；用户手动启用保存后，将其移动到独立文件夹并规范名称。
4. 删除 LOG、MOAPTIndexes 等中间文件；其他扩展名文件不做任何处理。
5. 在 MPF 程序头部写入或补全编制、审核、程序、图号、版次、机床、控制系统、日期和刀具等信息。
6. 检查程序头部之后是否存在 `M03`；不存在时自动补写。
7. 统计程序中的 F、S、X、Y、Z 参数最大值和最小值。
8. 检查 NC 程序的语法完整性和基本合理性，并明确提示错误位置。

## 4. 术语和文件定义

| 术语 | 定义 |
|---|---|
| MPF | 数控系统可执行的主程序文件，扩展名通常为 `.MPF`，大小写不敏感 |
| aptsource | CATIA 生成的 APT 源文件，扩展名通常为 `.aptsource`，大小写不敏感 |
| 中间文件 | LOG、MOAPTIndexes |
| 程序名 | 数控程序的交付名称，例如 `AG6D311A0101`，不含前缀、`_I` 后缀和文件扩展名 |
| 程序头部 | MPF 文件开头的 MSG 信息区域；对于 HASS，指自动插入的 MSG 区域 |
| 程序正文 | 程序头部结束后，以 NC 指令为主的内容区域 |

## 5. 输入和输出

### 5.1 输入

- 便携式 EXE 放入 CATIA 后处理输出目录后，程序启动自动将 EXE 所在目录作为输入目录。
- 不要求用户通过目录选择框输入目录；支持目录内的多个程序批量处理。
- 默认扫描 EXE 所在目录的第一层文件；是否递归扫描子目录应作为可配置选项，默认关闭。
- 支持的核心文件：`.MPF`、`.aptsource`。

### 5.2 输出目录结构

处理完成后，目录结构应满足以下规则：

```text
EXE 所在目录/
├─ AG6D311A0101.MPF
├─ AG6D311A0201.MPF
└─ aptsource/
   └─ 20260803_123456/
      ├─ AG6D311A0101.aptsource
      └─ AG6D311A0201.aptsource
```

- MPF 文件保留在 EXE 所在目录根目录。
- aptsource 文件不与 MPF 文件混合展示。默认处理方式为不保存并在确认后删除；用户手动勾选保存后，移动到 `aptsource/YYYYMMDD_HHMMSS/` 时间归档子目录。
- 仅处理 MPF、aptsource、LOG、MOAPTIndexes 四类文件；其他文件必须忽略，不展示、不移动、不删除、不写入报告。
- 默认不生成额外的配置文件来保存用户填写的程序信息；填写的信息直接写入 MPF 文件。程序运行期间可保存在内存中供批量处理复用。

## 6. 功能需求

### FR-01：目录选择和批量识别

1. 程序启动自动把 EXE 所在目录作为输入和输出目录。
2. 工具扫描目录并按扩展名识别 MPF、aptsource 和中间文件。
3. 界面将 MPF 保留表、APTSOURCE 文件表、待删除/待确认表分开显示，并显示预计动作。
4. 扩展名识别不区分大小写。
5. 无 MPF 的目录应给出提示并终止处理；只有 aptsource 的目录可按当前保存选项执行归档或清理。

### FR-02：程序名提取和文件重命名

#### 2.1 提取优先级

程序名按以下优先级确定：

1. MPF 内容中的明确程序名字段，例如 `MSG("PROGRAM:AG6D311A0101")` 或 HASS APT 中的 `PPRINT PROGNAME AG6D311A0101`。
2. 文件名中最后一个下划线 `_` 后的有效程序标识。
3. 去除已知前缀、`_I` 后缀和扩展名后的剩余部分。
4. 若仍无法确定，要求用户在处理前手动确认程序名。

#### 2.2 样例规则

```text
D0354F31311-201_AG6D311A0101.MPF
    → AG6D311A0101.MPF

D0354F31311-201_AG6D311A0101_I.aptsource
    → 默认确认后删除
    → 勾选保存时：aptsource/20260803_123456/AG6D311A0101.aptsource
```

#### 2.3 命名约束

- 程序名不能为空，默认允许中文、英文、数字、下划线和连字符；实际允许字符应可配置。
- 文件名不得包含路径分隔符、控制字符和 Windows 保留字符。
- 多个源文件生成相同目标文件名时，按修改时间自动采用最新文件覆盖目标；执行前必须逐项列出较旧文件、采用的最新文件和目标文件，不得静默处理。
- 重命名后的 MPF 文件和 aptsource 文件应使用同一程序名进行配对。

### FR-03：文件保留、移动和清理

1. 保留所有处理成功的 MPF 文件。
2. aptsource 默认不保存并在用户确认后删除；界面必须提供默认未勾选的“保存 APTSOURCE”选项。用户手动勾选后，才将匹配到的 aptsource 文件移动到 `aptsource/YYYYMMDD_HHMMSS` 时间子目录。无论是否保存，APTSOURCE 均不与 MPF 共用展示表，且仍参与本次扫描中的图号和刀具信息解析。
3. 默认删除以下文件：
   - `.LOG`
   - `.MOAPTIndexes`
   - 用户确认后认定为中间文件的其他文件
4. 未知扩展名不得直接删除，应列入“待确认文件”清单。
5. 清理前提供预览；用户取消时不移动、不删除任何文件。
6. 文件移动和删除失败时保留原文件，并在结果中显示失败原因。
7. 建议提供“先备份再清理”选项；备份目录位置由用户选择。
8. 新增或修改的特殊刀具信息保存到 `NCodeProcessData/special_tools.json`，不得混入 MPF 或 APT 表格。
9. 处理完成后默认不生成任何报告文件，仅在内存中保留本次处理结果；用户点击“导出报告”后，无需再次选择保存路径，程序应自动在当前处理目录的 `NCodeProcessData` 文件夹中生成带当前时间的 JSON 报告，并自动只保留最新三份。

### FR-04：程序头部信息

1. 若 MPF 开头没有任何目标 `MSG` 信息行，默认按 HASS 后处理结果处理，自动填写 `NC MACHINE:HASS`。
2. 若 MPF 开头已有目标 `MSG` 信息行但没有 `NC MACHINE`，默认按 V5-2500B 后处理结果处理并填写 `NC MACHINE:2500B`；已有非空 `NC MACHINE` 时加载并保留该值。
3. 缺少 `CONTROL SYSTEM` 时默认填写 `SIE840D`；已有非空 `CONTROL SYSTEM` 时不得更改。
4. 再次处理已有头部的 MPF 时，加载已有 `PROGRAM`、`NC MACHINE` 和 `PART VERSION` 作为预选参数；已有非空 `CONTROL SYSTEM` 和 `DATE` 无论是否启用覆盖选项都不得更改。`PART VERSION` 作为可编辑预选值，用户明确启用覆盖后仍可修改。
5. 程序信息输入区必须提供“应用”按钮。用户修改编制、审核、图号、版次、日期等信息后，只有点击“应用”才进入当前预览和处理；未点击“应用”时按默认值及原文件信息处理。
6. 头部结束后直接连接第一条程序正文，不额外插入空白行；原文件已有的格式空行按保留策略处理。
7. 图号和版次为必填项。点击“应用”或执行处理时任一为空，必须报错并放弃本次 MPF 修改。
8. 图号输入框默认保持为空。界面提供当前目录、上一级、上二级、上三级目录名称的选择框，默认选中上三级；只有用户点击“读取所选文件夹名作为图号”后才填入图号输入框，再点击“应用”后才能写入 MPF。
9. 扫描 APT 源文件时，应解析其头部 `$$ FILENAME` 和 `$$ PRODUCTNAME` 记录中的图号（例如 `D0354F31311-201.CATProcess`、`NCSetup_M-D0354F31311-201_11.47.18` 均解析为 `D0354F31311-201`），并以“APT提取”来源方法加入候选；候选仅供选择，不得自动应用。
10. 扫描 MPF 时应读取已有非空 `DRAWING NUMBER`，并以“MPF提取”来源方法加入候选。MPF 来源内部相同图号合并为一项，APT 来源内部相同图号合并为一项；MPF 与 APT 不得跨来源合并，即使图号相同也应分别保留两个候选。候选使用原生宽下拉框展示，来源方法与图号应完整可见。若全部 MPF 中只有一个明确图号，应自动预填到顶部图号栏。预填内容仍须点击“应用设置”后才参与处理。
11. 左侧选择 MPF 后，顶部编制、审核、图号、版次和日期字段应实时加载该程序已有值；字段不存在时使用已应用/保存的默认值。DATE 缺失时生成当前时间，格式为英文月份 `MMM dd HH:mm:ss yyyy`。

#### 4.1 信息字段

工具应支持以下字段的输入、编辑和写入：

| 字段键 | 写入格式 | 必填性 |
|---|---|---|
| BIANZHI | `MSG("BIANZHI:编制人姓名")` | 可配置，默认必填 |
| SHENHE | `MSG("SHENHE:审核人姓名")` | 可配置，默认必填 |
| PROGRAM | `MSG("PROGRAM:AG6D311A0101")` | 必填 |
| DRAWING NUMBER | `MSG("DRAWING NUMBER:零件图号")` | 可配置，默认必填 |
| PART VERSION | `MSG("PART VERSION:零件版次")` | 可配置，默认必填 |
| NC MACHINE | `MSG("NC MACHINE:2500B")` | 必填 |
| CONTROL SYSTEM | `MSG("CONTROL SYSTEM:SIE840D")` | 必填 |
| DATE | `MSG("DATE:Jul 31 09:38:23 2026")` | 默认自动填写，可编辑 |
| Tn | `MSG("T1:DIA=20.,TOOL_CONER=3,TOOL_ANGLE=-3.000000,TOOL_TYPE=反锥立铣刀")` | 按程序刀具数量生成，刀具类型和单边夹角可选 |

#### 4.2 处理已有头部

1. 识别大小写不敏感的 `MSG("KEY:VALUE")` 行，并允许行尾存在分号。
2. 已存在且值为空的字段，在冒号后填写用户指定内容。
3. 已存在且值非空的字段，默认保留原值；界面提供“覆盖已有值”选项。
4. 同一键出现多次时保留第一条有效记录，并将重复项报告为警告；用户确认后可合并或删除重复项。
5. 已存在字段应尽量保持原顺序、缩进、换行符和编码。
6. `PROGRAM` 字段应与规范化后的 MPF 文件名一致；不一致时提示并允许以用户确认值为准。
7. `DATE` 默认使用当前时间，格式为 `MMM dd HH:mm:ss yyyy`，月份使用英文缩写。
8. 刀具信息支持 `T1`、`T2` 等多个字段；工具应能从正文中的刀具调用和 APT 信息中预填直径、刀尖/圆角等可识别参数，无法识别的值留空供用户填写。自动识别出的所有值也必须允许用户修改或重新填写，最终以用户确认后的值为准。

#### 4.3 刀具信息输入和输出规则

1. 每把刀具至少应提供以下可编辑字段：刀具号、刀具直径 `DIA`、刀尖/圆角 `TOOL_CONER`、单边夹角 `TOOL_ANGLE`、刀具类型 `TOOL_TYPE`。
2. 后处理程序自动带出的刀具号、直径和刀尖/圆角等信息应自动回填到界面，但不得锁定，用户可以修改、补充或清空。
3. 后处理程序没有自动带出刀具信息时，用户可以手动新增刀具并填写全部刀具参数。
4. 刀具类型默认由用户手动选择，至少提供以下选项：
   - 普通立铣刀
   - 反锥立铣刀
   - 铅笔铣刀
   - T形刀
   - 钻头
   - 中心钻
5. 刀具类型列表应支持后续扩展，并支持用户输入和添加自定义刀具类型。
6. 刀具类型默认处于“未选择”状态。未选择刀具类型时，不得输出空的 `TOOL_TYPE` 参数，也不得输出 `TOOL_TYPE=`。
7. 刀具类型与该刀具的其他信息写在同一条 MSG 行中，参数之间使用英文逗号分隔。例如：

```text
MSG("T1:DIA=20.,TOOL_CONER=3,TOOL_TYPE=普通立铣刀")
```

8. 用户未选择刀具类型时，输出中仅保留已填写的其他参数。例如：

```text
MSG("T1:DIA=20.,TOOL_CONER=3")
```

9. 任一刀具子参数未填写时，只省略该子参数，不应输出空参数或多余逗号。
10. 一个程序使用多把刀具时，每把刀具各占一行，并按刀具号顺序输出。例如 `T1`、`T2`、`T3`。
11. 写入前应在界面中显示自动识别值与人工填写值，要求用户确认最终刀具信息。
12. 新增或修改刀具类型后，所有 `Tn` MSG 行必须继续位于程序头信息的最后，不得移动到 BIANZHI、SHENHE、PROGRAM 等头部字段之前。
13. APT 中 `CUTTER/` 的前两个参数分别作为刀具 `DIA` 和 `TOOL_CONER`；`TOOLNO/` 的第二个参数仅作为名义直径用于特殊刀具判定。
14. 当 `CUTTER/` 直径与对应 `TOOLNO/` 名义直径不一致时，自动判定为特殊刀具：`TOOLNO` 第四个参数为负数时类型为“反锥立铣刀”，为正数时类型为“铅笔铣刀”。
15. 特殊刀具的 `TOOLNO` 第四个参数为包含角，写入程序头时除以 2，使用英文参数名 `TOOL_ANGLE` 表示单边夹角；例如 `-6.000000` 写入为 `TOOL_ANGLE=-3.000000`。
16. 当 `CUTTER` 直径、圆角与 `TOOLNO` 名义直径、圆角一致，且不满足钻类角度条件时，自动类型为“普通立铣刀”。
17. 当 `TOOLNO` 第四个参数绝对值大于 100° 时归入钻类；续行存在钻尖高度或刀具类型码时判定为“钻头”，两者均为空时判定为“中心钻”。钻头和中心钻的角度仅用于识别，不输出 `TOOL_ANGLE`；该判定仅依赖 APT 参数规律，不限制刀具直径规格。
18. 自动生成 MPF 刀具信息时，同一程序最新修改的 APT 文件解析结果优先于 MPF 原有 `Tn` 信息和 `special_tools.json`；只有没有可用最新 APT 刀具信息时，才回退到 `special_tools.json`，再回退到 MPF 原有信息。用户在当前界面中明确编辑并应用的值可用于本次预览和处理。
19. 图形界面启动时采用适合 1920×1080 显示器的居中窗口模式，不自动全屏或最大化，并设置合理的最小窗口尺寸；各界面模块应随窗口自适应调整。主要表格、文本预览和差异视图各自提供一组垂直/水平滚动条，不得跨选项页叠加或浮空。程序修改差异应使用“修改前/修改后”双栏显示，并以红色标识删除内容、绿色标识新增内容；启动后应可直接查看刀具编辑区域。差异视图仅展示修改行及其上下各 3 行上下文，其余未修改内容在底部以蓝色汇总显示为“共 N 行未修改（已折叠）”。
20. 各表格默认列宽应按初始窗口宽度合理压缩，正常情况下无需操作横向滚动条即可看到全部列；用户仍可手动调整列宽查看超长内容。刀具数值字段统一保留三位小数。
21. 图号候选选择框前显示“图号候选”说明，确认按钮文字为“选取此项作为图号”。
22. 提供默认关闭的“自动添加换刀指令”选项。启用后，以当前刀具列表中最小刀具号作为首刀，在全部程序信息行之后、第一条程序正文之前插入 `TnM6`；程序正文中已有的刀具号引用同步修改为该刀具号，并合并重复的独立换刀行。未勾选时不得修改换刀指令。
23. 扫描阶段应为所有 MPF 预先完成参数统计，选择程序时直接展示，避免点击后卡顿；多个 MPF 的头部处理、统计和校验允许使用受控线程池并行执行。性能优化应包括：MPF 参数统计与校验合并为一次正文遍历、常用校验正则预编译、APT 仅读取头部元数据、每个程序仅完整分析最新 APT，并以流式方式提取 CUTTER/TOOLNO 刀具记录；重复扫描应复用未变化文件的读取及刀具解析缓存。

#### 4.4 缺少头部时的插入规则

1. 若文件没有任何目标 MSG 行，自动生成完整头部。
2. HASS 文件中的 `%` 程序起始标记应保留在第一行；MSG 头部插入在 `%` 之后、第一条 NC 指令之前。
3. 无 `%` 标记的文件，将 MSG 头部插入到文件第一条有效程序指令之前。
4. 头部结束后直接连接第一条 NC 正文，不由工具额外插入空白行。
5. 写入时保持原文件的行结束符风格（CRLF/LF）和可兼容数控系统的编码；无法可靠识别编码时必须中止该文件并提示。

### FR-05：M03 自动检查和补写

1. 检查范围仅限于程序头部结束后的正文区域，MSG 文本中的字符不计为 M03 指令。
2. `M03`、`M3`、大小写变体以及带分号的形式均视为同一指令。
3. 正文中已存在 M03 时不得重复添加。
4. 正文没有 M03 时自动补写一次：
   - 若存在首个有效 `S` 转速指令，将 `M03` 添加到该转速所在程序块中，默认紧跟在 `S` 数值之后；若该程序块带分号，则插入在分号之前，并保持后处理器格式。
   - 若不存在 S 指令，在第一条切削/运动指令之前插入独立的 `M03` 行。
5. 自动补写必须记录在处理报告中，并在预览中显示修改前后差异。
6. 若无法判断主轴旋转方向、转速或目标机床不允许自动补写，应将其标记为错误并要求用户确认，而不是盲目写入。
7. M03 的默认补写策略、插入位置和是否要求 S 值应可在程序设置中调整。

### FR-06：NC 参数统计

工具应扫描程序正文，忽略 MSG、注释、空行和程序起始/结束标记，统计以下参数：

| 参数 | 输出内容 |
|---|---|
| F | 出现次数、不同值列表、最小值、最大值 |
| S | 出现次数、不同值列表、最小值、最大值 |
| X | 出现次数、最小值、最大值 |
| Y | 出现次数、最小值、最大值 |
| Z | 出现次数、最小值、最大值 |

统计规则：

1. 支持正数、负数、小数和科学计数法（若目标控制系统支持）。
2. 仅统计明确写在程序块中的数值；未重复写出的模态坐标不重复计数。
3. 同一程序块中多个参数按各自出现位置统计。
4. 输出应保留原始有效小数位，另提供可排序的数值结果。
5. 参数缺失时显示“无数据”，不得误显示为 0。
6. 结果默认在界面中展示，可选导出 CSV 或 JSON；导出不是处理成功的必要条件。

### FR-07：程序完整性和合理性检查

#### 7.1 语法检查

- 检查无法解析的字符、非法数字、未闭合引号和异常控制字符。
- 检查程序块中的地址格式，例如 `G`、`M`、`X`、`Y`、`Z`、`F`、`S` 后应为合法数值（允许目标系统规定的无数值特殊代码）。
- 检查程序块编号 `N` 是否重复、倒序或出现非法格式。
- 检查程序结束标记是否存在，例如 `%`、`M30` 或 `M02`，具体规则按机床配置启用。

#### 7.2 完整性检查

- 检查程序名与文件名、`PROGRAM` 字段是否一致。
- 检查必填 MSG 字段是否存在且非空。
- 检查刀具调用是否包含对应刀具号；存在 `Tn` 时检查是否有合理的换刀指令（例如 `M06`，按机床配置启用）。
- 检查切削运动前是否有必要的主轴转速 `S` 和主轴启动 `M03`。
- 检查程序中是否存在孤立的坐标、进给或转速指令。

#### 7.3 合理性检查

- 默认将 `G00`（以及 `G0`）判定为错误，因为项目要求不应出现快速定位指令；该规则必须可配置为警告或允许。
- 检查 `F`、`S` 是否为负数或超出用户配置的上下限。
- 检查 X/Y/Z 是否超出机床行程范围；未配置机床范围时仅提示“未执行行程检查”。
- 检查同一程序段中互相冲突的 G/M 指令，例如同时出现互斥的运动模式。
- 检查 M03、M05、M08 等辅助指令的顺序是否符合配置规则。

#### 7.4 结果分级

| 级别 | 含义 | 对输出的影响 |
|---|---|---|
| 错误 | 程序不能安全交付或无法可靠解析 | 默认阻止输出，需用户修正或确认放行 |
| 警告 | 可能存在风险，但不一定影响运行 | 允许输出，必须在报告中显示 |
| 信息 | 统计或自动修复记录 | 不阻止输出 |

每条问题必须包含：文件名、行号、原始文本、问题类型、严重级别、建议处理方式。

### FR-08：预览、处理和报告

1. 提供“扫描预览”阶段，不修改文件。
2. 预览中显示：文件动作、重命名结果、头部修改、M03 修改、待删除文件和校验问题。
3. 用户确认后执行处理；执行过程中显示进度和当前文件。
4. 处理完成后生成汇总结果：成功数、失败数、跳过数、删除数、移动数、警告数和错误数。
5. 每个 MPF 文件提供详细报告和头部修改前后差异。
6. 发生异常时应尽可能完成其他独立文件处理，并在最终报告中集中列出失败项。

## 7. 推荐交互界面

### 7.1 主流程

```text
将 EXE 放入目录并启动 → 自动扫描识别 → 填写程序信息并点击“应用”
       → 分表预览保留 MPF、APTSOURCE 处理方式和待删除文件
       → 用户确认 → 文件整理与 MPF 修改 → NC 校验与统计 → 查看/导出报告
```

### 7.2 信息输入方式

- 支持单个程序编辑。
- 支持批量程序共享字段，例如编制人、审核人、NC MACHINE、CONTROL SYSTEM、DATE。
- 程序信息必须通过“应用”按钮提交；未点击“应用”时不改变当前预览配置。
- `PROGRAM`、`DRAWING NUMBER`、`PART VERSION`、刀具信息应支持按程序分别确认。
- 可从现有 MPF 自动读取已有字段并回填表单。
- 选中 MPF 后，以表格展示当前可解析的头部、刀具、校验和统计信息；刀具信息在独立编辑栏内修改。
- 不要求用户维护外部模板文件；如未来增加模板功能，应作为可选扩展。

### 7.3 布局与窗口行为

1. Windows 7、1366×768、100% DPI 为最低完整布局目标。程序默认以非全屏窗口启动，并按屏幕尺寸自适应；在该目标屏幕上默认窗口约为 1286×668，最小支持窗口约为 1180×650。低于该分辨率时仅保证窗口请求尺寸不超过屏幕，不承诺完整布局。
2. 主工作区应使用稳定的左右 50/50 网格，不采用可拖拽分隔条，避免启动或窗口重排出现分隔条闪动。
3. 顶部程序信息区应采用四行响应式布局：第一行为基本信息，第二行为处理选项，第三行为 G00 级别与自定义刀具类型，第四行为图号候选。图号候选行必须为“说明 + 可伸缩下拉框 + 固定选取按钮”，长内容不得挤掉选取按钮。
4. 应保留 Windows 原生 `ttk` 主题，不得强制切换为 `clam`。字体按系统可用顺序选择 `Microsoft YaHei UI`、`Microsoft YaHei`、`Segoe UI`、`Tahoma`，均不可用时回退 Tk 默认字体；Treeview 正文为 9pt，表头为 8pt 粗体。
5. 程序必须在运行时按实际字体 `measure` 配置表格宽度：校验列按“999 错 / 999 警”摘要内容预留空间；刀具号按实测文字宽度加安全留白配置；保留文件表和刀具表的所有中英文标题均须按粗体表头实测宽度加安全留白配置，确保 Windows 7 和 Windows 11 表头完整、不截断。
6. 在最低完整布局下，程序选择表和刀具表应默认无横向溢出、无需横向滚动。窗口扩展时，`source`、`target`、`TOOL_CONER`、`TOOL_ANGLE`、`TOOL_TYPE` 等伸缩列应获得额外宽度，`action`、`program`、`number`、`dia` 等紧凑列保持宽度；用户手动拉宽长文本列后，底部水平滚动条必须可用，且后续窗口缩放不得覆盖手动列宽。
7. 源文件和目标文件名可仅在界面显示层增加间隔以改善辨识；不得改变 `FilePlan` 中的实际路径、重命名结果或导出的处理报告。
8. 刀具编辑器应始终预留约 230px 的可见宽度。启动延后回调与控件销毁应安全协同：关闭窗口时取消待执行回调，且不得遗留 Tk 回调异常。
9. “自定义刀具类型”输入框与“添加类型”按钮必须紧邻排列，右侧留作可伸缩空间；不得因窗口尺寸而将输入、添加操作分散或挤压 G00 设置。

## 8. 配置要求

以下设置应在程序设置界面提供，并在当前运行期间生效：

- EXE 所在目录作为默认输入/输出目录。
- 是否保存 aptsource（默认关闭）；启用后使用的子目录名称和时间归档格式 `YYYYMMDD_HHMMSS`。
- 是否递归扫描子目录。
- 待删除扩展名白名单。
- 程序名提取规则和允许字符。
- 已有非空 MSG 值的处理方式：保留或覆盖。
- 必填 MSG 字段。
- M03 自动补写策略。
- `G00/G0` 的检查级别。
- 程序结束标记、M06、S/F 范围和机床行程等校验规则。
- 文件编码和换行符策略（自动识别/强制指定）。

编制、审核/校对和自定义刀具类型的用户设置不得以配置文件写入 NC 输出目录；在 Windows 上保存到当前用户设置，移动 EXE 后仍可复用。

配置优先保存在内存中；若实现“记住上次输入”，应使用应用自身设置存储，并不得把配置文件写入 NC 输出目录。

## 9. 非功能需求

### 9.1 安全性和可恢复性

- 删除和覆盖操作必须二次确认。
- 目标文件名冲突时默认由修改时间最新的文件覆盖；仅在最新文件成功写入后清理较旧重复源文件。
- 建议提供处理前备份或回收站式恢复能力。
- 任何文件修改都应先读取并校验成功，再以临时文件写入，最后原子替换。
- 文件被其他程序占用时不得强制覆盖，应提示用户关闭占用程序。

### 9.2 兼容性

- Windows 7 为必须通过验收的运行平台，不得将 Windows 10/11 作为最低运行要求。
- Windows 7 环境下，1366×768、100% DPI 必须满足本文件 7.3 所定义的最低完整布局。
- 应兼容 Windows 7 的常见 32 位和 64 位环境；如采用不同便携发布包，应分别提供对应版本。
- 程序必须采用免安装便携式发布方式，用户解压程序压缩包后即可运行，或直接运行单文件可执行程序，不得要求执行安装向导。
- 程序不得强制依赖 Microsoft Store、WebView2 或只有较新 Windows 才提供的系统组件。
- 若程序依赖运行库，发布包必须自带与 Windows 7 兼容的运行库；不得要求用户另行联网下载或安装运行库。
- 程序首次运行不得要求管理员权限，不得强制写入系统目录、注册表启动项或 Windows 安装数据库。
- 用户可以将整个程序目录复制到其他 Windows 7 计算机或移动存储设备后直接运行。
- 用户数据、处理报告和临时文件应默认写入程序目录下的用户可写目录或用户指定目录，不得写入系统受保护目录。
- 可同时兼容 Windows 8.1、Windows 10 和 Windows 11，但不得影响 Windows 7 的核心功能。
- 支持 CRLF、LF 换行符。
- 至少兼容 ASCII、UTF-8、UTF-8 BOM 和常见中文编码；编码不确定时提示用户选择。
- 不改变程序正文中未涉及的 NC 指令、注释和空白格式。

### 9.3 免安装发布要求

- 发布物至少提供一种便携版本：
  - 方案 A：包含可执行文件及其运行库的 ZIP 压缩包，解压后直接运行；或
  - 方案 B：包含全部依赖的单文件可执行程序。
- 发布包应包含使用说明、版本信息和示例配置说明（如有），但不得通过安装程序注册文件关联或创建卸载项。
- 程序退出后不得在系统临时目录留下无法清理的大量临时文件；必要的临时文件应集中放在程序目录的临时子目录，并支持安全清理。
- 当程序目录位于只读位置时，应提示用户选择可写的输出目录，不得因无法写入程序目录而静默失败。

### 9.4 性能

- 单个程序最大文件大小、批量文件数量应可配置；在常规工作站上，100 个中等规模 MPF 文件应在合理时间内完成扫描和处理。
- 统计和校验不应因界面刷新导致明显卡顿。

### 9.5 可审计性

- 记录处理时间、输入目录、输出目录、工具版本、用户确认项和每个文件的变更摘要。
- 报告中不得省略自动补写 M03、重命名、移动和删除等关键动作。

## 10. 异常处理

| 场景 | 处理要求 |
|---|---|
| 找不到 MPF | 提示用户，停止需要 MPF 的处理流程 |
| MPF 与 aptsource 无法配对 | 分别列出，允许用户单独处理或取消 |
| 程序名提取失败 | 要求用户手动输入或跳过该文件 |
| 同名文件已存在 | 默认采用修改时间最新的文件覆盖；执行确认时逐项提示，写入成功后清理较旧重复文件 |
| 文件无权限/被占用 | 跳过该文件并提示关闭占用程序 |
| 编码无法识别 | 不写入文件，要求用户指定编码 |
| 文件内容无法解析 | 保留原文件，生成错误报告 |
| 自动 M03 位置不明确 | 不自动修改，生成需确认的错误 |
| 删除失败 | 保留文件并报告失败原因 |

## 11. 验收标准

### AC-01：V5-2500B 样例

使用 `样例文件/数控程序/V5-2500B` 执行处理后，应满足：

- 每个 MPF 文件重命名为仅含程序名的形式，例如 `AG6D311A0101.MPF`。
- 每个 aptsource 文件不出现在 MPF 表中；默认预览为不保存并在确认后删除。手动勾选保存后，移动并重命名为 `aptsource/YYYYMMDD_HHMMSS/AG6D311A0101.aptsource`。
- LOG、MOAPTIndexes 等文件按清理规则处理。
- 已有 MSG 行中空字段被补全，非空字段默认保留。
- 正文中没有 M03 的程序会被自动补写；已有 M03 的程序不重复补写。
- 能显示 F/S/X/Y/Z 的统计结果和完整性检查结果。

### AC-02：HASS 样例

使用 `样例文件/数控程序/HASS` 执行处理后，应满足：

- 保留 HASS 原有 `%` 起始标记、分号风格和正文指令。
- 在 `%` 之后、首条 NC 指令之前插入完整 MSG 头部。
- 无头部的 HASS 文件默认填写 `NC MACHINE:HASS`；有头部的 V5-2500B 文件默认填写 `NC MACHINE:2500B`；控制系统均为 `SIE840D`。
- 已存在 `S5000M03` 的程序不得再次插入 M03。
- 文件名、PROGRAM 字段和程序正文中的程序名应保持一致。

### AC-03：安全性

- 预览阶段不得修改文件。
- 用户取消确认后不得发生移动和删除。
- 同名目标文件不得被静默覆盖。
- 每个自动修改均可在报告中追溯。

### AC-04：Windows 7、免安装和刀具信息

- 程序能够在未联网的 Windows 7 环境中解压后直接启动、扫描、修改和输出文件，不需要安装。
- 程序首次运行不要求管理员权限，不创建卸载项、注册表启动项或系统级文件关联。
- 将整个程序目录复制到另一台 Windows 7 计算机后，仍可直接运行核心功能。
- 后处理程序未提供刀具信息时，可以手动新增并填写刀具信息。
- 后处理程序已经提供刀具信息时，自动识别值可以被人工修改。
- 选择“普通立铣刀”等刀具类型后，类型信息与 DIA、TOOL_CONER 写入同一条 Tn MSG 行。
- 未选择刀具类型时，输出行中不得出现 `TOOL_TYPE` 空参数。
- 多把刀具能够分别设置不同的刀具类型，且按刀具号分别输出。
- 默认刀具类型包含普通立铣刀、反锥立铣刀、铅笔铣刀、T形刀，并支持新增自定义类型。

## 14. 本次实现补充规则

1. 图号和版次为处理必填项。用户未填写或未点击“应用”时，程序必须报错并放弃 MPF 修改。
2. EXE 所在目录名称可作为图号建议，但只能通过“读取文件夹名作为图号”及“应用设置”后写入 MPF。
3. 无目标 MSG 头部的 MPF 默认视为 HASS，机床填写 HASS；有目标 MSG 头部的 MPF 默认视为 V5-2500B，机床填写 2500B；控制系统统一为 SIE840D。
4. MPF、APTSOURCE 和待删除/待确认文件分别使用独立表格展示。APTSOURCE 默认不保存，只有用户手动勾选保存后才归档到 `aptsource/YYYYMMDD_HHMMSS/`；未勾选时在执行确认后删除，但扫描阶段仍用于图号和刀具解析。
5. 头部与第一条 NC 正文之间不得由工具额外插入空白行。
6. 特殊刀具信息保存于 EXE 所在目录的 `NCodeProcessData/special_tools.json`；处理报告默认不写入磁盘，仅在用户点击“导出报告”后输出。点击后不弹出路径选择框，报告自动保存到当前目录的 `NCodeProcessData` 文件夹，文件名包含当前时间，并仅保留最新三份。
7. 默认刀具类型为普通立铣刀、反锥立铣刀、铅笔铣刀、T形刀、钻头和中心钻，并支持新增自定义类型；刀具 MSG 始终位于程序头信息最后。

8. 校验规则必须检查进给速度 F 和主轴转速 S：F0 为严重错误；当程序主要 F 值处于千位范围而出现个位或两位数 F 值时给出警告；程序包含多个不同 S 值时给出警告。
9. “全部程序信息”使用独立窗口展示，每个 MPF 占一行，列出 F、S、X、Y、Z 的出现次数、最小值、最大值及 G00 检查结果；程序启动时不自动打开，顶部提供按钮供用户手动查看。参数统计页保留当前选中程序的单程序统计，并同样显示各参数出现次数。
10. 左侧程序表的校验列独立显示；存在错误或警告时，仅对应校验单元格使用红色加粗字体突出显示。
11. 执行目录处理前必须展示处理摘要并由用户确认。确认明细较少时使用简洁确认框；重复文件、待删除文件等明细较多或文本较长时，必须使用固定初始大小的独立确认页面。独立页面的明细区域应同时支持纵向和横向滚动，底部“确认执行”和“取消”按钮应固定可见，不得因明细数量增加而移出屏幕。
