# 1. 产品概述

## 1.1 程序用途

NC 程序后处理工具用于整理 CATIA 后处理输出目录，对 MPF 程序进行头部信息补全、刀具信息识别、参数统计和规则校验，并按用户确认的方案处理 APTSOURCE、LOG 和 MOAPTIndexes 文件。

程序采用免安装单文件方式发布。将 `NCodeProcess.exe` 放入待处理目录并双击启动，即可自动扫描 EXE 所在目录，无需选择输入目录。

## 1.2 主要功能

- 自动识别并批量处理 MPF 程序。
- 自动区分 HASS 与 2500B 后处理格式。
- 写入或补全程序头部信息，并保留不允许覆盖的已有字段。
- 从最新 APTSOURCE 中提取图号和刀具信息。
- 支持普通立铣刀（自动细分为圆鼻/球头/平底）、反锥立铣刀、铅笔铣刀、T 形刀、钻头、中心钻及自定义刀具类型。
- 统计 F、S、X、Y、Z 的出现次数、最小值和最大值。
- 检查 F0、异常低 F 值、多 S 值、G00、结束标记等问题。
- 可选补写 M03 和换刀指令。
- 预览修改前后差异，并在执行前进行二次确认。
- 手动导出 JSON 处理报告，并自动只保留最新三份。

## 1.3 支持的文件类型

| 扩展名 | 用途 | 默认处理方式 |
|---|---|---|
| `.MPF` | 数控主程序 | 保留、规范文件名并按设置修改内容 |
| `.aptsource` | CATIA APT 源文件 | 参与图号和刀具解析；默认确认后删除，可勾选归档 |
| `.LOG` | 后处理中间日志 | 确认后删除 |
| `.MOAPTIndexes` | 后处理中间索引 | 确认后删除 |

除以上四类文件外，其他文件不会被展示、移动、删除或写入报告。

# 2. 使用前准备

## 2.1 系统要求

- Windows 7 或更高版本。
- 普通用户权限即可运行，无需管理员权限。
- 无需安装 Python、Anaconda 或其他运行库。
- 程序所在目录必须允许当前用户读写。
- 最低完整布局支持 Windows 7、1366×768、100% DPI；程序默认非全屏启动，并按屏幕尺寸自适应。在该分辨率下默认窗口约为 1286×668，最小支持窗口约为 1180×650。低于此分辨率时仅保证窗口请求尺寸不超过屏幕，不保证所有区域完整显示。
- 保留 Windows 原生 `ttk` 主题，不强制使用 `clam`。界面优先使用系统可用的 `Microsoft YaHei UI`、`Microsoft YaHei`、`Segoe UI`、`Tahoma`，均不可用时使用 Tk 默认字体；因此在 Windows 7 和 Windows 11 上均以本机实际字体为准。

## 2.2 部署方法

1. 从便携包中取得 `NCodeProcess.exe`。
2. 将 EXE 复制到需要处理的 CATIA 后处理输出目录。
3. 确认目录内包含需要处理的 MPF 等文件。
4. 双击 EXE 启动。

> [!NOTE]
> 程序始终把 EXE 所在目录作为当前处理目录。需要处理其他目录时，请复制或移动 EXE 到目标目录后再启动。

## 2.3 建议的首次使用方式

1. 复制一份真实生产目录作为测试副本。
2. 将 EXE 放入副本目录。
3. 完成扫描、预览和执行。
4. 使用机床要求或原始程序进行人工复核。
5. 确认规则符合项目要求后，再用于正式目录。

> [!NOTE]
> 同一目录下重复启动程序会提示“程序已在本目录运行”并退出，避免两个实例同时写配置/报告造成冲突；不同目录下的程序可以同时运行。

# 3. 五步快速上手

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | 将 EXE 放入待处理目录并启动 | 自动扫描当前目录 |
| 2 | 填写图号、版次及其他信息 | 建立本次处理参数 |
| 3 | 点击“应用设置” | 刷新所有程序的处理预览 |
| 4 | 选择程序并检查解析、校验、统计和刀具信息 | 确认修改内容正确 |

# 4. 主界面说明

## 4.1 界面区域

| 界面区域 | 主要内容 | 使用说明 |
|---|---|---|
| 自动扫描目录 | 当前目录、重新扫描、包含子目录、保存 APTSOURCE | 控制扫描范围和 APTSOURCE 保存方式 |
| 程序信息 | 编制、审核、图号、版次、日期和自动处理选项 | 设置写入 MPF 的程序头信息 |
| 顶部操作栏 | 查看全部程序信息、扫描状态、导出报告、确认执行 | 执行全局操作 |
| 左侧文件区 | 保留/归档文件、APTSOURCE 文件、待删除文件 | 查看所有计划动作并选择 MPF |
| 右上审查区 | 解析信息、校验问题、参数统计、修改差异 | 审核当前选中程序 |
| 右下刀具区 | 刀具表和刀具参数编辑 | 修改当前程序的刀具信息 |

### 4.1.1 布局与响应规则

主工作区固定为左右 50/50 网格，不提供可拖拽分隔条；启动和窗口重排时不会产生分隔条闪动。顶部“程序信息”采用四行响应式布局：第一行为基本信息，第二行为处理选项，第三行为 G00 级别与自定义刀具类型，第四行为图号候选，避免单行内容相互挤压。

Treeview 正文使用 9pt，表头使用 8pt 粗体。程序启动时按实际字体的测量结果配置表格：校验列按“999 错 / 999 警”这一摘要内容预留空间；刀具号以及保留文件表和刀具表的每个英文/中文表头，均以粗体表头的实测宽度加安全留白确定最小列宽。这可避免 Windows 7 与 Windows 11 因默认字体不同而截断表头。

程序选择表和刀具表在最低完整布局下默认无横向溢出、无需横向滚动。窗口变宽时，程序选择表的 `source`、`target` 列，以及刀具表的 `TOOL_CONER`、`TOOL_ANGLE`、`TOOL_TYPE` 列会随可用宽度扩展；`action`、`program`、`number`、`dia` 等列保持紧凑。若手动拉宽长文本列，表格底部水平滚动条可查看未显示内容；随后缩放窗口时，手动设定的列宽仍会保留。

右下刀具编辑器固定预留约 230px 可见宽度，编辑字段和操作按钮不会因表格列扩展而被压缩。窗口关闭时，程序会取消尚未执行的启动回调并释放关联界面资源，避免 Tk 回调残留错误。

## 4.2 顶部扫描选项

### 包含子目录

默认不勾选，只扫描 EXE 所在目录第一层。勾选后会扫描子目录，但会自动跳过已有 `aptsource` 归档目录和 `NCodeProcessData` 数据目录。

### 保存 APTSOURCE（按时间归档）

默认不勾选。未勾选时，APTSOURCE 仍用于本次图号和刀具解析，但在用户确认执行后删除。

勾选后，APTSOURCE 会保存到：

```text
aptsource\YYYYMMDD_HHMMSS\程序名.aptsource
```

切换该选项后程序会重新扫描，以便在 APTSOURCE 表中更新预计动作。

# 5. 程序信息设置

## 5.1 信息字段

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 编制 BIANZHI | 否 | 程序编制人员信息 |
| 审核/校对 SHENHE | 否 | 程序审核或校对人员信息 |
| 图号 | 是 | 零件或产品图号 |
| 版次 | 是 | 图纸或程序版本 |
| 日期 | 自动预填 | MPF 已有日期优先；不存在时使用当前日期时间 |
| NC MACHINE | 自动处理 | 无头部程序默认 HASS；已有目标头部默认 2500B |
| CONTROL SYSTEM | 自动处理 | 默认 SIE840D；已有非空值不修改 |

> [!IMPORTANT]
> 图号和版次必须填写，并且必须点击“应用设置”。仅在输入框中填写但未点击“应用设置”，执行时仍会报错并放弃处理。

## 5.2 应用设置

程序信息支持两种应用方式：

- **全部应用**：对目录内全部 MPF 应用本次输入，重新扫描并重新生成所有处理预览（不写入文件）。
- **应用所选**：对保留/归档表中选中的 MPF（可多选）应用本次输入并生成预览（不写入文件）；未选择程序时提示。

两种方式都会先校验图号和版次是否完整，并保存本次已应用的程序信息。

**覆盖已有非空 MSG 字段**：勾选后才允许修改可编辑头部字段（编制/审核/图号/版次）；未勾选时按默认逻辑执行（保留已有非空值、补空缺/插入缺失）。`NC MACHINE` 与 `CONTROL SYSTEM` 已有非空值始终不变；程序名统一通过右键「修改程序名」修改；`DATE` 由程序自动维护——程序发生实际变更时自动更新为变更发生时间，无需手动修改（选项旁「?」图标可查看说明）。

- 勾选后：点击「全部应用」/「应用所选」生成并展示预览（显示修改效果），确认无误后点击「确认并执行处理」将更改写入文件；
- 未勾选时：应用操作仅生成并展示预览（默认逻辑），不修改已有值。

程序已有填好的程序头信息时，点击程序后顶部程序信息栏会显示这些信息；对已应用过修改的程序，顶部信息栏保持显示应用后的值，不会被文件旧值刷回。

## 5.3 保存编制/校对

“保存编制/校对”用于保存常用人员信息。数据保存在当前 Windows 用户设置中，不会写入 NC 处理目录。EXE 在同一台计算机、同一用户下移动后仍可继续使用。

## 5.4 图号候选

图号候选下拉框可能包含：

- 当前目录名称。
- 向上第 1、2、3 层文件夹名称。
- APTSOURCE 头部提取结果。
- MPF 已有 `DRAWING NUMBER` 提取结果。

候选行采用“说明 + 可伸缩下拉框 + 固定‘选取此项作为图号’按钮”的布局。选择候选后，点击该按钮才会写入顶部图号输入框；随后仍需点击“应用设置”。候选说明较长时，下拉框优先占用可用宽度，选取按钮保持可见和可操作。

## 5.5 自动处理选项

| 选项 | 默认值 | 作用 |
|---|---|---|
| 覆盖已有非空 MSG 字段 | 不勾选 | 勾选后才允许修改可编辑字段（编制/审核/图号/版次）；未勾选按默认逻辑（保留已有值） |
| 自动补写 M03 | 勾选 | 程序缺少 M03 时按可识别的 S 指令补写 |
| 自动添加换刀指令 | 不勾选 | 在头部后插入首刀 `TnM6`，并统一正文已有 T 刀号；程序包含多把刀具时对该程序禁用并跳过，预览给出警告，执行确认页明确列出 |
| G00 级别 | error | 将 G00/G0 作为错误、警告或允许项处理 |

已有非空 `NC MACHINE` 和 `CONTROL SYSTEM` 不会被覆盖；`DATE` 在程序发生实际变更时自动更新为变更发生时间；勾选“覆盖已有非空 MSG 字段”后，编制/审核/图号/版次按表单值覆盖，应用操作生成预览，确认并执行处理时写入文件。

# 6. 扫描结果与文件预览

## 6.1 保留/归档文件表

该表主要显示 MPF 文件，包括计划动作、程序名、源文件和目标文件名。选择一条 MPF 后，右侧立即显示该程序的详细信息。

校验列显示错误和警告数量，并按“999 错 / 999 警”摘要内容预留安全宽度。存在异常时，仅该校验单元格使用红色加粗文字突出显示。源文件和目标文件名前的少量间隔只为提升界面可读性，不会写入文件路径、重命名计划或处理报告。

在该表右键菜单可对选中的 MPF 执行：**编辑程序代码**（选中 1 条）、**修改程序名**（选中 1 条，更新目标文件名与头部 PROGRAM 字段）、**对比所选两条程序**（选中 2 条）。多个程序无法自动确定程序名时，会一次性打开列表页逐一填写，不再逐个弹窗。

## 6.2 APTSOURCE 文件表

该表与 MPF 分开显示。处理方式可能为：

- `不保存（删除）`：默认方式，执行确认后删除。
- `保存并归档`：勾选保存选项后，移动到时间归档目录。

即使显示为不保存，扫描阶段仍会使用最新 APTSOURCE 提取图号和刀具信息。

## 6.3 待删除文件表

显示计划清理的 LOG 和 MOAPTIndexes 文件。执行前会在确认页面中再次列出。

## 6.4 目标文件名冲突

多个源文件生成相同目标名称时：

1. 按文件修改时间选择最新文件作为有效来源。
2. 执行确认页面逐项显示较旧文件、采用的最新文件和目标文件。
3. 只有最新文件成功写入后，程序才清理较旧重复文件。
4. 最新文件写入失败时，较旧文件保持不变。

# 7. 刀具信息识别与编辑

## 7.1 刀具信息来源优先级

1. 当前程序匹配到的最新 APTSOURCE 刀具信息。
2. 用户在界面中明确编辑并应用的刀具信息。
3. `NCodeProcessData\special_tools.json` 中保存的特殊刀具信息。
4. MPF 已有的 Tn MSG 刀具信息。

APTSOURCE 是否最终归档，不影响其在本次扫描中的最高解析优先级。

## 7.2 可识别刀具类型

| 刀具类型 | 主要识别依据 | 输出参数 |
|---|---|---|
| 圆鼻立铣刀 | CUTTER 直径与 TOOLNO 名义直径一致，0 < 圆角 < 直径一半 | DIA、TOOL_CONER、TOOL_TYPE |
| 球头立铣刀 | 直径与圆角一致，且圆角 = 直径一半 | DIA、TOOL_CONER、TOOL_TYPE |
| 平底立铣刀 | 直径与圆角一致，且圆角 = 0 | DIA、TOOL_CONER、TOOL_TYPE |
| 反锥立铣刀 | 两个直径不一致且夹角为负 | DIA、TOOL_CONER、单边 TOOL_ANGLE、TOOL_TYPE |
| 铅笔铣刀 | 两个直径不一致且夹角为正 | DIA、TOOL_CONER、单边 TOOL_ANGLE、TOOL_TYPE |
| T 形刀 | 两个直径不一致、无夹角且直径比 ≥ 2（初步识别）；也可用户选择或保存配置 | 按可用参数输出 |
| 钻头 | APT 参数呈钻类规律并包含钻尖特征 | DIA、TOOL_TYPE，不输出角度 |
| 中心钻 | APT 参数呈中心钻规律 | DIA、TOOL_TYPE，不输出角度 |

「普通立铣刀」仍保留在类型下拉中，用于手动指定或兼容旧配置；自动识别时按圆角细分为圆鼻/球头/平底立铣刀。

刀具数值统一保留到小数点后三位。特殊刀具的 APT 夹角写入程序头前会除以 2，输出单边夹角。

## 7.3 编辑刀具

1. 在左侧选择一个 MPF。
2. 在右下刀具表选择需要修改的刀具行。
3. 修改刀具号、DIA、TOOL_CONER、TOOL_ANGLE 或刀具类型。
4. 点击刀具编辑区的应用/保存按钮。
5. 检查右上“解析信息”和“修改差异”是否已更新。

已有刀具信息会自动加载到编辑框，不需要重新手工录入全部参数。

## 7.4 添加自定义刀具类型

在“自定义刀具类型”输入名称，点击紧邻输入框的“添加类型”。输入框和按钮右侧保留可伸缩空白，既保持两者连续操作，也不会挤压同一行的 G00 设置。自定义类型保存到 `NCodeProcessData\special_tools.json`，并可在刀具类型下拉框中选择。

# 8. 参数统计与校验问题

## 8.1 单程序参数统计

选择 MPF 后，“参数统计”页显示当前程序中 F、S、X、Y、Z 的：

- 出现次数。
- 最小值。
- 最大值。
- G00/G0 检查结果。

统计在扫描阶段提前完成，选择程序时直接展示。

## 8.2 全部程序信息

点击顶部最左侧“查看全部程序信息”，打开独立窗口。每个 MPF 占一行，集中展示 F、S、X、Y、Z 的次数、最小值、最大值以及 G00 检查结果。

## 8.3 主要校验规则

| 校验项目 | 级别或表现 | 用户处理建议 |
|---|---|---|
| F0 | 严重错误 | 必须确认是否为错误进给指令 |
| F 明显低于/高于本程序主体水平（IQR 箱线图法动态判定） | 警告 | 核对该行进给是否误输（如单位或参数错误） |
| 程序存在多个不同 S 值 | 警告 | 确认是否确需切换主轴转速 |
| G00/G0 | 由 G00 级别控制 | 按机床和项目规范处理 |
| 缺少结束标记 | 错误或警告 | 检查 `%`、M30 或 M02 |
| M03 缺失 | 可自动补写或提示 | 核对主轴转速及启动位置 |
| 程序名或语法不完整 | 错误/警告 | 根据提示行号修正源程序 |

错误通常会阻止相应 MPF 写入；警告用于提醒人工复核，不一定阻止输出。

F 离群按工艺阶段分组检测：程序会先按行上下文把每个 F 归入移动/退刀（Z≥抬刀高度阈值，默认 20）、进刀（Z≤0 下刀）或切削（带 X/Y 的加工）阶段，再在**每个阶段内部**统计常见进给档位（出现 ≥2 次视为正常，如切削 900 与抬刀 5000 并存都不报），只检查该阶段内出现 1 次的孤立值是否明显低于或高于本阶段常见档位（低于最低档 ×0.1 或高于最高档 ×3）。这样样例中 300~6000、800~8000、30~300 等宽跨度波动均不误报（50 个样例 0 误报），而“切削段突然冒出 F20”“3000 主体突然冒出 15000”这类孤立异常仍会提示。某阶段 F 值连续变化（无常见档位）时回退 IQR 极端值标准（倍数默认 3）。判定参数（IQR 倍数、低值/高值比例、抬刀高度阈值）可在「程序设置 → 校验规则 → F 离群与 S 警告」页调整并持久化保存，多 S 值警告默认开启；留空或输入非正数时回退默认值。

## 8.4 设置保存与导出

「程序设置」对话框分两页，每页按分类分组：**基本设置**（文件处理：文件编码、程序名允许字符、单文件大小上限、扫描文件数量上限；文件类型：待删除扩展名、主程序扩展名、输出扩展名；目录与存储：APTSOURCE 归档子目录、处理前询问备份、配置保存位置）与**校验规则**（基础检查：结束标记/M06/S；工艺校验：G00 级别、必填 MSG 字段、M03 补写位置、F/S 上下限；F 离群与 S 警告；输出格式：换行策略、辅助指令顺序）。全部值都会保存，重启程序后自动恢复；各选项旁的 **?** 说明按钮可查看字段含义（点击弹出说明）。单文件大小上限与扫描文件数量上限留空或填 0 表示不限制，超过大小上限的 MPF 会被跳过并提示，超过数量上限时停止扫描并提示。保存位置可在「基本设置 → 目录与存储 → 配置保存位置」选择：

- `registry`（默认）：保存到当前 Windows 用户注册表；
- `appdata`：保存到用户数据目录 `%APPDATA%\NCodeProcess\settings.json`；
- `home`：保存到用户主目录下的 `settings.json`。

切换保存位置后，程序会**清空另外两处可能残留的旧配置**，避免旧值影响下次读取。点击「恢复默认」会恢复全部设置项默认值，保存位置自动切回注册表，并同步清空另外两处可能残留的配置。点击「导出设置…」可把当前全部设置导出为 JSON 文件（自选保存路径）。

程序启动时会**自动检测三个保存位置**（注册表、AppData、用户主目录）——哪个位置有已保存的配置，哪个位置就是本次设置的保存位置，「配置保存位置」下拉会同步显示；三个位置均无配置时默认使用注册表。

## 8.5 修改差异

修改差异页面分别展示修改前和修改后内容，并提供红绿色高亮差异。为避免显示整份大程序，只保留修改行上下各三行；连续未修改内容使用“xx 行未修改”概述。

# 9. 确认并执行处理

## 9.1 执行前检查清单

- 图号和版次已填写。
- 已点击“应用设置”。
- 已检查所有红色校验单元格。
- 已核对程序目标文件名。
- 已确认 APTSOURCE 是删除还是归档。
- 已检查刀具类型、直径、圆角和特殊角度。
- 已查看关键程序的修改差异。

## 9.2 执行确认页面

点击“确认并执行处理”后：

- 内容较少时使用简洁确认框。
- 重复文件或待删除文件较多时使用固定大小的独立确认页面。
- 独立页面顶部显示处理摘要，中部可滚动查看完整明细。
- “确认执行”和“取消”按钮固定在页面底部。

选择“取消”不会发生任何移动、删除或写入。

确认明细会展示本次操作的变动对象与变动内容摘要：每个待修改 MPF 的源文件 → 目标文件及修改说明（如补全/插入头部字段、补写 M03、重命名等），待删除文件与重复文件处理清单；不展示完整程序内容。

> 执行前默认会询问“是否先将待处理文件备份到 backup\\时间戳 目录”；可在“程序设置 → 基本设置”中关闭“处理前询问备份”，关闭后执行前不再询问、也不自动备份。

## 9.3 执行过程

程序使用临时文件和原子替换方式写入 MPF。文件被其他程序占用、目录不可写或目标写入失败时，会保留原文件并记录失败原因。

# 10. 导出处理报告

## 10.1 报告生成方式

处理完成后报告仅保存在内存中，不会自动写入磁盘。需要报告时点击“导出报告”，无需选择路径。程序启动与扫描阶段不会自动生成 `NCodeProcessData` 目录或任何日志文件；导出报告时仅生成**单个 JSON 报告文件**，运行日志完整内嵌在报告 JSON 的 `runtime_log` 字段中，不再生成磁盘日志文件。

报告自动保存到：

```text
当前处理目录\NCodeProcessData\ncodeprocess-report-YYYYMMDD_HHMMSS.json
```

## 10.2 报告保留规则

程序只保留最新三份 `ncodeprocess-report-*.json`。生成新报告时会自动删除最旧报告。

## 10.3 报告内容

- 输入目录、输出目录及开始/完成时间。
- 成功、失败、跳过、移动、删除、错误和警告数量。
- 每个文件的计划动作和实际状态。
- 修改说明和 unified diff。
- 校验问题及参数统计。
- 本次运行的事件日志（`runtime_log`，完整内嵌报告，不再生成磁盘日志文件）。
- 工具版本、报告来源（GUI/CLI）、用户确认项与处理时生效的配置快照。
- 每个文件的目标路径与程序名来源（MSG / PPRINT / 文件名 / 手动确认）。

报告可使用独立的 `NCodeProcessReportViewer.exe` 进行可视化查看。

# 11. 文件处理规则

## 11.1 MPF 头部默认逻辑

| MPF 状态 | 默认机床 | 控制系统 |
|---|---|---|
| 没有目标 MSG 头部 | HASS | SIE840D |
| 已有目标 MSG 头部但没有 NC MACHINE | 2500B | SIE840D |
| 已有非空 NC MACHINE | 保留已有值 | 保留已有或补充 SIE840D |

再次处理已有程序时，已有 `PROGRAM`、`NC MACHINE`、`PART VERSION` 会作为预选值加载；已有 `NC MACHINE` 和 `CONTROL SYSTEM` 不修改，`DATE` 在程序发生实际变更时自动更新为变更发生时间。

## 11.2 程序头部顺序

程序信息行按固定顺序组织，刀具 Tn MSG 始终放在程序头信息的最后。工具不会在程序头和第一条 NC 正文之间额外插入空白行。

## 11.3 目录输出示例

未保存 APTSOURCE：

```text
处理目录\
├─ NCodeProcess.exe
├─ 程序A.MPF
├─ 程序B.MPF
└─ NCodeProcessData\
   ├─ special_tools.json
   └─ ncodeprocess-report-YYYYMMDD_HHMMSS.json
```

保存 APTSOURCE：

```text
处理目录\
├─ 程序A.MPF
├─ aptsource\
│  └─ YYYYMMDD_HHMMSS\
│     └─ 程序A.aptsource
└─ NCodeProcessData\
```

# 12. 典型使用场景

## 12.1 处理无头部 HASS 程序

1. 将 EXE 放入 HASS 后处理目录。
2. 启动后选择一个 MPF，确认解析为 HASS。
3. 填写图号和版次并应用。
4. 核对插入的 MSG 头部、M03 和刀具信息。
5. 确认执行。

程序会保留 HASS 原有 `%` 起始行和分号风格。

## 12.2 处理已有头部的 2500B 程序

1. 启动程序并查看已加载的 PROGRAM、NC MACHINE、PART VERSION 和 DATE。
2. 仅修改确需变化的可编辑字段。
3. 不勾选覆盖时，已有非空 MSG 字段默认保留。
4. 检查刀具和参数统计后执行。

## 12.3 仅使用 APTSOURCE 解析刀具但不保存

1. 保持“保存 APTSOURCE”不勾选。
2. 扫描后选择 MPF，核对刀具信息来自最新 APTSOURCE。
3. 执行确认页面会显示 APTSOURCE 将被删除。
4. 确认后 MPF 使用解析出的刀具信息，APTSOURCE 被清理。

## 12.4 保存 APTSOURCE 归档

1. 勾选“保存 APTSOURCE（按时间归档）”。
2. 等待重新扫描完成。
3. 在 APTSOURCE 表中确认处理方式为“保存并归档”。
4. 执行后检查 `aptsource\时间目录`。

# 13. 常见提示与故障处理

| 现象或提示 | 可能原因 | 处理方法 |
|---|---|---|
| 图号和版次未通过应用设置提交 | 信息为空或填写后未点击应用 | 填写完整并点击“应用设置” |
| 无法确定程序名 | 文件内容和文件名均无法提取有效名称 | 按提示手工输入程序名 |
| 目标文件已存在 | 同名文件占用或覆盖条件不满足 | 关闭占用程序并核对冲突明细 |
| 文件无权限或被占用 | MPF 正在编辑、杀毒软件或机床软件占用 | 关闭占用程序后重新扫描和执行 |
| 扫描速度较慢 | 文件数量多、文件很大或递归扫描 | 关闭不必要的递归扫描，等待后台统计完成 |
| 刀具信息不是预期值 | 最新 APTSOURCE 与 MPF 现有信息不同 | 核对最新 APTSOURCE，并在刀具编辑区人工修正 |
| 报告未自动出现 | 报告默认不输出 | 处理完成后点击“导出报告” |
| 看不到某些文件 | 文件类型不在四类白名单中 | 属于正常忽略行为 |
| 程序窗口内容显示不全 | 屏幕缩放或窗口小于最小尺寸 | 调整 Windows 缩放或使用不低于最小窗口尺寸 |

> [!WARNING]
> 不要直接对唯一一份正式生产数据进行首次规则验证。删除和重命名属于实际文件操作，取消确认前不会执行，但确认后会按预览内容处理。

# 14. 安全使用建议

- 首次处理新机床、新项目或新后处理格式时使用目录副本。
- 执行前重点检查红色校验信息、F0、异常 F 值和多个 S 值。
- 对特殊刀具核对 DIA、TOOL_CONER 和单边角度。
- 对重复目标文件逐项确认最新文件是否正确。
- 保留必要的原始数据备份和工艺审批记录。
- 执行过程中不要同时使用其他程序修改同一批 MPF。
- 报告只保留最新三份，重要报告应及时复制到项目归档位置。
