# NC 程序后处理工具用户手册

> 适用程序：NCodeProcess 1.0.0。  
> 本手册可公开发布；示例均使用通用目录和虚构程序名。

## 1. 程序用途

NCodeProcess 用于批量整理 CATIA 后处理目录：识别 MPF/APTSOURCE，规范程序名和 MSG 头部，识别刀具，检查 M03、M06、F/S 和程序结构，预览文件变化，并在确认后完成改写、重命名、归档和清理。

程序是 Windows 便携应用，不需要安装，不修改系统文件关联，也不需要网络。

## 2. 使用前准备

1. 先复制一份待处理目录，首次使用不要直接操作唯一原件。
2. 将 `NCodeProcess.exe` 放入待处理目录。
3. 确认目录中包含需要处理的 MPF；APTSOURCE 可选。
4. 双击 EXE。程序默认扫描 EXE 所在目录。

程序使用自定义图标（EXE 文件图标与运行窗口标题栏/任务栏图标一致）。
最低完整界面目标是 Windows 7、1366×768、100% DPI。Windows 10/11 可正常使用；更低分辨率可能需要滚动或放大窗口。

## 3. 推荐操作流程

### 第一步：扫描

启动后程序自动扫描当前目录。需要扫描子目录时勾选“包含子目录”后重新扫描。
扫描采用两阶段：文件列表（含归档/清理动作与目标）会立即出现，随后程序在后台逐文件完成深度分析，状态栏显示进度；分析完成前“全部应用/应用所选/确认并执行处理”按钮保持禁用。选中文件的分析结果会优先处理并在完成后刷新右侧预览。

结果分为：

- 保留/处理的主程序；
- APTSOURCE；
- 待删除中间文件；
- 重名或无法确认的文件。

扫描只是预览，不会改写文件。

### 第二步：填写程序信息

填写或确认：

- 编制；
- 审核/校对；
- 图号；
- 版次；
- 机床；
- 控制系统；
- 日期。

图号和版次是执行修改前的必填项。图号候选需要人工选择，不会自动写入。

### 第三步：检查刀具和设置

选择一个 MPF 后检查右侧刀具表。可以新增、修改、删除刀具，也可以添加自定义刀具类型。

常见刀具字段：

- `DIA`：直径；
- `TOOL_CONER`：刀具圆角；
- `TOOL_TYPE`：刀具类型；
- `TOOL_ANGLE`：角度。

数值在写入 MSG 时统一为三位小数。

### 第四步：应用设置并复核预览

点击“应用设置”或对选中程序应用设置。该操作只重新计算预览，不会写盘。

重点核对：

- 源文件与目标文件名；
- MSG 头部；
- 刀具号和正文 T 指令；
- 错误、警告和提示；
- 修改差异；
- APT 规划信息；
- F 抬刀平面分段、离群/复核和分布表。

### 第五步：确认并执行

点击处理按钮后进入最终确认页。确认备份、清理和覆盖范围，再执行写盘。

任何错误级问题都应优先处理。警告允许继续，但应人工确认；提示不阻止输出。

## 4. 主界面说明

### 4.1 顶部区域

- 包含子目录：递归扫描；默认关闭。
- 保存 APTSOURCE：启用后归档到 `aptsource/<时间戳>/`；默认关闭时在确认后删除。
- G00 级别：错误、警告或允许。
- 程序信息：用于生成或更新 MSG 头部。
- 图号候选：从目录和 APT 信息中提取，仅供人工选择。
- 程序设置：打开持久化配置。

### 4.2 文件表

校验摘要为紧凑格式“E错 / W警 / I提”（E=错误、W=警告、I=提示）；有错误级时红色加粗，仅有警告时橙色，仅有提示时蓝色，无任何问题时灰色。
校验摘要为“错 / 警 / 提”三项计数；有错误级时红色加粗，仅有警告时橙色，仅有提示时灰色。

典型动作：

- keep/update：保留或更新；
- move：归档；
- delete：待删除；
- duplicate/review：重名或需人工确认；
- skip：因错误或限制跳过。

### 4.3 右侧页面

- MSG/刀具：已有信息与计划写入值；
- 识别数据：APT、F 抬刀平面分段、离群/复核、分布表和证据；
“识别数据”页的抬刀高度框自动填入检测值；需要修改时直接编辑后按回车或点击“确认”，仅切换页签不会把自动值当作设置提交。
- 参数统计：F/S/X/Y/Z 数量、范围和 G00 数；
- 校验问题：错误、警告、提示及建议；
- 修改差异：原文与计划输出的逐行比较；“对比所选两条程序”向左右展示差异并带行号。

## 5. 程序设置

设置分为“基本设置”和“校验规则”。问号按钮显示该项的详细含义。

### 5.1 基本设置

| 设置 | 默认值 | 说明 |
|---|---|---|
| 文件编码 | 自动 | 自动识别 UTF-8、GB18030 等 |
| 待删除扩展名 | `.log,.moaptindexes` | 仅在最终确认后删除 |
| 主程序扩展名 | `.mpf` | 可增加其他文本程序扩展名 |
| 输出扩展名 | `.MPF` | 重命名后的主程序扩展名 |
| APTSOURCE 归档目录 | `aptsource` | 仅在启用保存时使用 |
| 处理前询问备份 | 开启 | 建议保持开启 |
| 单文件大小上限 | 不限制 | 留空或 0 表示不限制 |
| 扫描文件数量上限 | 不限制 | 留空或 0 表示不限制 |
| 配置保存位置 | 注册表优先 | 可切换 AppData 或用户目录 |

### 5.2 基础校验

- 要求结束标记：默认开启；接受 `%`、M30、M02。
- 要求 M06：默认关闭。
- 要求 S 转速：默认关闭。
- 必填 MSG：可按车间要求启用或关闭部分字段。
- M03 补写位置：默认紧随首个有效 S 程序段；也可独立成行。
- 辅助顺序：M03、M05、M08、M09 的先后检查默认开启。
- 换行策略：默认保持原文件，也可强制 CRLF 或 LF。

### 5.3 F/S 范围

默认硬边界：

- F：20～10000；
- S：500～12000。

留空可关闭对应一侧的范围检查。该范围是安全边界，不是“合法档位列表”。

### 5.4 F 离群校验

F 离群校验采用**抬刀平面分段对比**，参数固定、无需调整：

- 抬刀平面：程序自身重复出现的最高 Z 面（如 HASS 的 Z100）；
- 分段：从抬刀平面下刀、加工、再回到抬刀平面为一个“来回”段；
- 判据：全程序出现 ≤2 次的 F 值，若与其他段所有 F 的相对差距都超过 30%，输出提示；
- 分级：差距 >60% 为警告，30%~60% 为复核；
- 豁免：罕见值的所有出现行都是抬刀平面以下的纯 Z 下刀/钻入行，且满足「越深越慢」「同深同速」时视为轴向切入，不提示；平面上的定位/抬刀行不豁免；
- 单段程序：与同目录其它程序的常见档位（≥2 个程序使用）对比；目录中没有参照时只输出 F 分布表（值 × 次数 × 首次行号），不做自动判定。

“抬刀高度阈值”仍用于 APT 轨迹页的抬刀次数重算，不参与 F 离群判定。不能通过调整参数或设置固定 F 白名单来消除提示。

## 6. F 异常结果怎么读

程序以抬刀平面为界把程序切成多个“来回”段，比较段与段之间的 F。同一段内是连续加工，F 应保持一致；段与段之间才是换工序的合法分界。

### 6.1 离群告警（警告）

某个 F 值全程序只出现 ≤2 次，且与其他所有段的值差距都超过 60%，属于明显异常（如多打一个 0 的 F15000）。应检查原始行、其他段的值和最小差距。

### 6.2 复核提示

差距在 30%~60% 之间，可能是该段特有的合法值（如单次使用的工艺进给），也可能是误输。必须结合轨迹和工艺人工确认。

### 6.3 轴向切入豁免

罕见值若全部出现在纯 Z 运动行（有 Z、无 X/Y），程序按轴向切入/下刀类合法动作直接豁免，不提示。这条规则与具体 F 数值无关，因为不同零件/程序的钻入档位不同。

### 6.4 APT 参考列

APT 参考显示某个 F 是否在配对 APT 的 `FEDRAT` 集合附近（约 ±10%）。它只是辅助上下文：

- 在 APT 内不代表一定正确；
- 不在 APT 内也不代表一定错误；
- 没有配对 APT 时显示「无 APT 参考」，不显示「不在 APT 档位内」；
- 核心离群仍依据当前 NC 程序自身的段间对比。

### 6.5 单段程序

程序只有一次下刀/抬刀时，程序与同目录其它程序的常见档位（≥2 个程序使用）对比，判据与段间对比一致。目录中没有可参照的程序时，只输出 F 值分布表（每个 F × 出现次数 × 首次行号，并显示 F 最小值/最大值范围），只出现一次的值会标注“请人工确认”。未提示不等于程序正确，硬边界、语法和 APT 交叉校验仍然有效。

## 7. APT 信息与交叉校验

有配对 APTSOURCE 时，程序显示机床、后处理、生成时间、操作、主轴、进给、冷却、装夹刀具、轨迹范围和退刀平面。

主要提示：

- 主轴方向不一致：错误；
- F/S 或刀具几何不一致：警告；
- 程序名不一致：警告；
- 冷却、装夹顺序、DATE：提示。

没有 APTSOURCE 时，MPF 仍可正常处理，只是不执行相关交叉校验。

## 8. 自动改写注意事项

### 8.1 M03

默认在首个有效 S 程序段补写 M03。正文存在 M04 时不会自动补写，以免正反转冲突。

### 8.2 自动换刀

自动添加换刀只适用于单刀程序。发现多把刀具或多个正文 T 号时，程序会跳过自动换刀并要求人工确认。程序内已有正确的 TnM6 时不会修改；不正确的 TnM6 会在原行修正（T 号或补 M6），不删除重新加；只有没有独立换刀指令时才会在正文首行新增 TnM6。

### 8.3 覆盖已有字段

“覆盖已有字段”不会无条件覆盖所有内容。机床和控制系统等受保护字段按当前规则保留；PROGRAM、DATE 按程序名和实际改动同步。

### 8.4 注释

括号注释和分号后的文本不参与指令判断。不要把需要执行的 G/M/F/S/T 指令写在注释中。

## 9. 报告导出

GUI 点击“导出报告”后，在程序目录的 `NCodeProcessData` 中生成一个 `ncodeprocess-report-<时间>.json`，默认只保留最新三份。

报告包括：

- 处理汇总与运行环境（平台 / Python 版本 / 位数）、扫描分类统计；
- 每个文件的动作、目标、状态、失败原因、问题和差异；
- 处理后 MSG 头部快照、自动换刀跳过原因与重复目标裁决关系；
- 参数统计；
- APT 规划与轨迹；
- F 抬刀平面分段、离群/复核、分布表和证据；
- 实际配置快照（含文件类型、覆盖、命名规则等全部处理配置）；
- 用户确认与扫描警告；
- 完整内嵌运行日志 `runtime_log`。

程序不再生成独立日志文件，`log_path` 是兼容字段，当前为空。建议使用配套 NCodeProcessReportViewer 查看 JSON。

## 10. CLI 使用

预览：

```powershell
python -m ncodeprocess -i "C:\NC-DEMO\JOB-001"
```

执行：

```powershell
python -m ncodeprocess -i "C:\NC-DEMO\JOB-001" --yes --drawing-number DEMO-001 --part-version A
```

导出 JSON：

```powershell
python -m ncodeprocess -i "C:\NC-DEMO\JOB-001" --yes --drawing-number DEMO-001 --part-version A --json-report "C:\NC-DEMO\report.json"
```

不带 `--yes` 永远只预览。使用 `python -m ncodeprocess --help` 查看完整选项。

## 11. 常见问题

### 启动后没有文件

确认 EXE 与 MPF 位于同一目录；若文件在子目录，启用递归扫描；检查主程序扩展名设置。

### 图号候选为空

候选只是辅助。可人工填写图号；程序不会自动从目录名强制写入。

### 点击应用后磁盘文件没变化

“应用设置”只刷新预览。必须进入最终确认并执行，才会写盘。

### 程序提示只读或备份失败

不要强行关闭保护。确认目录权限、文件是否被其他软件占用以及备份位置是否可写。

### F 告警很多

先看是硬边界、离群告警还是复核提示，再检查原始行、其他段的值和最小差距。不要尝试通过调整参数或设置固定 F 白名单来消除提示；单段程序的 F 分布表提示不代表程序错误。

### APT 中有这个 F，为什么仍提示

APT 只提供辅助证据。若该 F 在当前 NC 中全程序罕见且与其他段差距过大，仍会提示；这可以发现 APT 档位被用在错误工序段的情况。

### 报告查看器找不到报告

把查看器放到处理目录，或点击“打开报告文件”直接选择 JSON。报告也可以放在 `NCodeProcessData` 中。

## 12. 安全建议

1. 首次处理新后处理格式时使用副本。
2. 保持“处理前询问备份”开启。
3. 执行前先解决 error，再审查 warning。
4. 对自动换刀、主轴方向、APTSOURCE 清理和覆盖目标进行人工确认。
5. 使用发布包内 `SHA256SUMS.txt` 核对 EXE 完整性。
6. 不要用“与上一版 EXE 字节完全相同”判断构建真伪；发布构建每次使用随机字节码加密密钥。
