# NC 程序后处理工具用户手册

> 适用程序：NCodeProcess 1.0.0。  
> 本手册可公开发布；示例均使用通用目录和虚构程序名。  

## 1. 程序用途与使用前准备

### 1.1 程序用途

NCodeProcess 用于批量整理 CATIA 后处理目录：

- 识别 MPF 主程序、APTSOURCE 源文件与可清理的中间文件（LOG/MOAPTIndexes）；
- 规范程序名与 MSG 头部（编制、审核、图号、版次、机床、控制系统、日期、刀具）；
- 自动补写 M03、添加/修正换刀指令；
- 校验程序语法、G00、结束标记、F/S 参数与 F 离群；
- 与配对 APTSOURCE 交叉校验（主轴、进给、刀具、冷却等）；
- 预览全部改动，确认后批量改写、重命名、归档、清理；
- 导出单个 JSON 审计报告，供 NCodeProcessReportViewer 查看。

程序是 Windows 便携应用：**不需要安装，不修改系统文件关联，不需要网络**。最低完整界面目标是 Windows 7、1366×768、100% DPI；Windows 10/11 正常使用，更低分辨率需滚动或放大窗口。

### 1.2 使用前准备

1. **先复制一份待处理目录**——首次使用不要直接操作唯一原件；
2. 将 `NCodeProcess.exe` 放入待处理目录；
3. 确认目录中有 MPF（APTSOURCE 可选）；
4. 双击 EXE。程序自动扫描 EXE 所在目录，**不需要选择输入目录**。

### 1.3 排故

| 现象 | 处理 |
|---|---|
| 双击 EXE 无反应 | 检查是否被安全软件拦截；尝试右键"以管理员身份运行"验证；确认系统为 Windows 7 及以上 |
| 提示"已在本目录运行" | 同一目录已有一个实例在运行（单实例保护，防止双 EXE 竞态写配置）。找到并关闭已有窗口，或从其他目录启动 |
| 杀毒软件报警 | 发布版使用字节码加密与 UPX 压缩，属防破解设计。以发布包内 `SHA256SUMS.txt` 校验 EXE 完整性后放行 |

## 2. 启动与主界面总览


启动后主窗口从上到下依次为：

1. **程序运行配置**工具栏：程序设置…、包含子目录、保存 APTSOURCE、重新扫描目录；
2. **程序信息**区（四行）：基本信息（编制/审核/图号/版次/日期）、处理选项、图号候选、自定义刀具类型；
3. **动作栏**：查看全部程序信息、状态栏、扫描进度条、导出报告、确认并执行处理；
4. **主体双栏**：左侧三个文件表（保留/归档、APTSOURCE、待删除），右侧五个详情页签（解析信息、校验问题、参数统计、识别数据、修改差异）；
5. 底部**当前程序刀具信息（可编辑）**区。

程序启动后自动扫描 EXE 所在目录。扫描分两阶段：文件列表（含归档/清理动作与目标）立即出现；随后后台逐文件完成深度分析，状态栏显示进度，分析完成前"全部应用/应用所选/确认并执行处理"按钮保持禁用。**扫描只是预览，不会改写文件。**

表格单元格内容被列宽截断时，鼠标悬停约 1.5 秒会弹出浮窗显示完整内容；表格支持横向、纵向滚动，列宽可手动拖动。

## 3. 顶部工具栏（程序运行配置）

| 控件 | 说明 | 操作 | 排故 |
|---|---|---|---|
| 目录标签 | 显示当前扫描目录（EXE 所在目录） | — | 目录不对时，把 EXE 放到正确目录后重新启动 |
| 程序设置… | 打开持久化配置对话框（见 §9） | 点击后弹出"程序设置"窗口 | 设置不生效时，确认点过"确定"（点"取消"会回滚全部改动） |
| 包含子目录 | 递归扫描子目录 | 勾选后点"重新扫描目录" | 勾选后列表无子目录文件：确认文件扩展名是主程序扩展名（见 §9.1） |
| 保存 APTSOURCE（按时间归档） | 默认关闭 = 确认处理后**删除** APT 源文件；开启 = 归档到 `aptsource/<时间戳>/` | 勾选即自动重新扫描 | 归档位置见设置"APTSOURCE 归档子目录"；归档动作在最终确认页二次确认 |
| 重新扫描目录 | 重新扫描整个目录 | 点击后状态栏显示进度 | 扫描中不要重复点击；"重新扫描目录"只刷新列表，不会写入文件 |

## 4. 程序信息区（四行布局）

### 4.1 基本信息行：编制 / 审核/校对 / 图号 / 版次 / 日期

| 输入框 | 说明 | 默认值来源 |
|---|---|---|
| 编制 BIANZHI | 编制人，写入 MSG `BIANZHI` | 上次保存的配置 |
| 审核/校对 SHENHE | 审核人，写入 MSG `SHENHE` | 上次保存的配置 |
| 图号 | 图号，写入 MSG `DRAWING NUMBER`，**必填** | 扫描完成时若全目录唯一则自动预填；也可从"图号候选"选取 |
| 版次 | 版次，写入 MSG `PART VERSION`，**必填** | 同上 |
| 日期 | 日期，写入 MSG `DATE` | 当前时间；选中文件时回填该文件头部 DATE |

操作要点：

- **图号和版次为必填项**：未填写或未点击"全部应用/应用所选"，处理按钮不放行（提示"图号和版次未通过应用设置提交，已放弃本次修改"）；
- 选中左侧某程序后，输入框自动回填该程序头部的编制/审核/图号/版次/日期（已有值）或默认值；
- 修改输入框内容**不会立即生效**——必须点击"全部应用"或"应用所选"生成预览，最终写盘还需"确认并执行处理"。

排故：

| 现象 | 处理 |
|---|---|
| 点击"全部应用"提示"信息不完整" | 图号或版次为空。填写后再点 |
| 填了图号版次还是不能处理 | 处理前必须**点过"全部应用/应用所选"并成功**（应用后按钮才放行处理） |
| 日期自动变成当前时间 | 正常。程序确有改动时 DATE 才更新；无改动保留原值；有配对 APT 时优先采用 APT 生成时间 |
| 输入框被自动填充了值 | 可能来自：全目录唯一图号/版次预填、选中文件头部回填。均为可编辑的建议值，人工确认后再应用 |

### 4.2 处理选项行

| 控件 | 说明 | 操作 |
|---|---|---|
| 全部应用 | 用当前表单值对**全部 MPF** 重新计算内存预览（不写盘） | 点击后状态栏显示"正在应用…"，完成后右侧预览与表格校验列刷新 |
| 应用所选 | 仅对**选中行**重新计算预览 | 先单击选中一个程序，再点击 |
| 保存编制/校对 | 把编制、审核写入配置存储（注册表/AppData/用户目录） | 点击即可；下次启动自动回填 |
| 覆盖已有非空 MSG 字段 | 勾选 = 预览按新值覆盖可编辑头字段；不勾 = 只补空缺字段 | 悬停蓝色"?"查看允许覆盖的字段说明（仅编制/审核/图号/版次等可编辑字段，机床/控制系统受保护） |
| 自动补写 M03 | 默认开启：正文无 M03 时按策略补写 | 关掉则不做 M03 补写 |
| 自动添加换刀指令 | 默认关闭：开启后为单刀程序添加/修正 TnM6 | 多刀程序自动跳过并提示原因（见 §10.2） |

排故：

| 现象 | 处理 |
|---|---|
| 点"全部应用"后磁盘文件没变 | 正常——"应用"只刷新预览。写盘必须走"确认并执行处理" |
| 换刀指令没加上 | 该程序是多刀程序，或正文有多个 T 号引用（自动跳过并提示）；或"自动添加换刀指令"未勾选 |
| 覆盖了不想改的字段 | 关闭"覆盖已有非空 MSG 字段"；受保护字段（机床/控制系统）不会被普通覆盖 |

### 4.3 图号候选行

- **图号候选**下拉框：列出当前目录及向上三级目录名 + APT 头部提取的图号候选；
- **选取此项作为图号**：把下拉框选中的候选写入图号输入框。

操作：选择下拉框中的候选 → 点"选取此项作为图号" → 图号输入框填入该值。

排故：图号候选为空——候选只是辅助，可直接人工填写图号，程序不会自动从目录名强制写入。

### 4.4 自定义刀具类型行

- **输入框**：输入新的刀具类型名（如"燕尾刀"）；
- **添加类型**：把新类型加入刀具类型下拉列表并保存到 `NCodeProcessData/special_tools.json`（默认内置：普通立铣刀、圆鼻立铣刀、球头立铣刀、平底立铣刀、反锥立铣刀、铅笔铣刀、T 形刀、钻头、中心钻）。

排故：添加的类型下次启动还在吗——在。特殊刀具类型保存在 EXE 所在目录的 `NCodeProcessData/special_tools.json`；旧版 `NCPostProcessData/special_tools.json` 也会自动读取兼容。

## 5. 动作栏

| 控件 | 说明 |
|---|---|
| 查看全部程序信息 | 打开"全部程序参数统计"窗口（20 列：F/S/X/Y/Z 次数/最小/最大、G00、GOTO 点数、圆弧数、抬刀次数），初始禁用，扫描完成且有 MPF 时启用 |

| 状态栏 | 显示当前阶段：扫描中、后台分析 n/N、应用中、处理中、完成等 |
| 扫描进度条 | 后台逐文件分析进度，扫描期间显示 |
| 导出报告 | 初始禁用；处理完成后启用。把最近一次处理报告存为 `NCodeProcessData/ncodeprocess-report-<时间>.json`（只保留最新三份），弹窗提示路径 |
| 确认并执行处理 | 初始禁用。点击后进入最终确认（见 §8），确认后后台执行写盘 |

排故：

| 现象 | 处理 |
|---|---|
| 按钮一直是灰色 | 后台分析未完成，或目录无 MPF，或图号/版次未应用。按状态栏提示处理 |
| 导出报告按钮不可用 | 还没有执行过处理（报告来自"确认并执行处理"的结果） |
| 报告保存到哪 | EXE 所在目录的 `NCodeProcessData`，自动保留最新三份 |

## 6. 左侧文件表

左侧为三页签：**保留 / 归档文件**、**APTSOURCE 文件**、**待删除文件**。

### 6.1 保留 / 归档文件表（主表）

列：动作 / 程序名 / MPF 源文件 / 目标。右侧独立的"校验列"与主表同步滚动，以紧凑格式显示 **E错 / W警 / I提** 三项计数，并按最高级别着色：有错误红色加粗、仅有警告橙色、仅有提示蓝色、无问题灰色。

常见动作：`keep/update`（保留/更新）、`move`（归档）、`delete`（待删除）、`duplicate/review`（重名或需人工确认）、`skip`（因错误或限制跳过）。

操作：

- **单击一行**：右侧立即刷新该程序的解析信息、校验问题、参数统计、识别数据、修改差异与刀具表；
- **右键菜单**：编辑程序代码（选中 1 条）、修改程序名（选中 1 条）、对比所选两条程序（恰好选中 2 条）；
- **多选**：按住 Ctrl/Shift 单击可选择多行（对比需要恰好 2 条）。



排故：

| 现象 | 处理 |
|---|---|
| 右键菜单项灰色 | 编辑/改名需选中 1 条，对比需选中恰好 2 条 MPF |
| 校验列全红 | 该程序有错误级问题（如缺结束标记、F0、程序名不一致）。点击行看右侧"校验问题"页签逐条处理 |
| 程序名列为空 | 程序名无法自动确定（MSG/PPRINT/文件名都识别失败）。右键"修改程序名"手动命名；或扫描时在批量确认窗口填写 |

### 6.2 APTSOURCE 文件表

列：处理方式 / 程序名 / APTSOURCE 文件 / 处理目标。展示 APT 源文件是"保存并归档"还是"删除"（由"保存 APTSOURCE"开关决定）。归档目标为 `aptsource/<时间戳>/`。

### 6.3 待删除文件表

列：类型 / 动作 / 文件 / 说明。列出按扩展名规则（默认 `.log`、`.moaptindexes`）识别出的中间文件；只有最终确认清理后才会删除。

## 7. 右侧详情页签

### 7.1 解析信息

两列（字段/解析项目、当前值）展示：源文件、规范程序名、目标文件、文件编码，以及 MSG 头部每个字段的"已有 / 处理后"两行值——**这里是核对头部改动的主入口**。

排故：处理后值与预期不同——检查"覆盖已有非空 MSG 字段"开关与图号/版次/日期输入值；PROGRAM 随程序名同步。

### 7.2 校验问题

列：行/类型/级别/原始文本/建议。逐条列出该程序的语法、参数、结构问题。级别含义：

- **error**（错误）：通常阻止该程序写入，必须修正；
- **warning**（警告）：允许继续但应人工确认；
- **info**（提示）：如 F 复核、APT 提示。

常见问题与建议：

| 问题类型 | 建议 |
|---|---|
| 缺结束标记（%） | 按设置"要求程序结束标记"；添加 %/M30/M02 或关闭该检查 |
| G00/G0 | 按 G00 级别（error/warning/allow）处理；确属合法抬刀可改警告或允许 |
| F0 / F 越界 | F0 是严重异常必改；越界值对照设置 F/S 上下限 |
| N 号不递增 | 警告，人工确认是否分段重排 N 号 |
| 程序名不一致 | 头部 PROGRAM 与规范程序名不同，按建议统一 |
| 未闭合引号 / 控制字符 | 修正原始行 |

### 7.3 参数统计

列：程序/参数/出现次数/最小值/最大值/G00 检查。展示当前程序 F/S/X/Y/Z 的统计（每参数一行 + G00 行）。F/S 还有去重值列表供快速查看档位。

### 7.4 识别数据

合并 APT 轨迹与 F 离群检测两个面板：

**APT 轨迹**（来源：最新 APTSOURCE）：

- XYZ 行程：APT 规划轨迹的行程范围；
- 抬刀高度输入框 + 确认按钮：自动识别值预填；**只有人工修改后按回车或点"确认"才提交**（仅切换页签/失焦不会误提交）；提交后按程序记忆、重算抬刀次数并同步报告与全部程序统计；
- 抬刀次数：按当前高度统计的抬刀次数。

**F 离群检测**：分段统计（抬刀平面/段数/容差）、APT 参考、检测结论、检测证据明细表（行/F值/结论/原因/段/次数/最小差距/参照值/APT参考/原始行）、单段分布表（无参照时供人工判定）。

排故：修改抬刀高度后次数没变——需要按回车或点"确认"提交，仅切页签不生效。

### 7.5 修改差异

左"修改前"、右"修改后"逐行对比：删除行红色、新增行绿色、修改行黄色、折叠脚注蓝色。**核对写入内容的主入口**。

## 8. 确认并执行处理

点击"确认并执行处理"后：

1. **前置校验**：图号/版次必须已通过"应用设置"提交，否则放弃本次修改；无任何变更时提示放弃；
2. **最终确认**：汇总待处理文件数。明细短则原生确认框；明细长（>10 项或 >1200 字符）弹出"确认目录处理"窗口（粗体汇总 + 可滚动处理明细 + 取消/确认执行）；

3. **备份询问**：若设置开启"处理前询问备份"，询问是否先备份到 `backup\<时间戳>\`；
4. **后台执行**：状态栏显示进度（n/总数），写盘、归档、清理按确认口径执行；
5. **完成**：弹窗提示成功/失败/移动/删除计数；此时"导出报告"按钮可用。

排故：

| 现象 | 处理 |
|---|---|
| 点击后提示"图号和版次未通过应用设置提交" | 先点"全部应用/应用所选"成功，再执行处理 |
| 处理一半出错 | 查看状态栏与弹窗错误；备份目录（若已备份）可用于恢复。单文件原子写入保证不会留下半写文件 |
| 想中止处理 | 处理/扫描进行中关闭窗口会弹确认框；确认关闭将中断操作（可能留下未完成改动），建议等待完成 |
| 重复目标文件 | 重名目标先裁决（取最新文件），较旧源文件按确认口径清理；裁决关系记录在报告 `duplicate_winner` |

## 9. 程序设置对话框

点"程序设置…"打开，两页：**基本设置** / **校验规则**。



每项行尾的蓝色"?"显示该项详细说明。底部按钮：恢复默认（全部回默认并清理残留配置）、导出设置…（保存 JSON）、确定（校验并保存生效）、取消（回滚本次改动）。快捷键：回车=确定，Esc=取消。

### 9.1 基本设置页

| 分组 | 设置项 | 说明与操作 |
|---|---|---|
| 文件处理 | 文件编码 | auto/utf-8/utf-8-sig/gb18030/gbk/gb2312/cp1252。auto 自动识别（UTF-8 BOM→UTF-8→GB18030）；含 NUL 的疑似二进制/UTF-16 文件拒绝处理 |
| 文件处理 | 程序名允许字符 | 默认 `^[A-Za-z0-9_一-鿿-]+$`（中文/字母/数字/下划线/连字符）；改后点"恢复默认"还原 |
| 文件处理 | 单文件大小上限 | 字节数；留空或 0 = 不限制。超限主程序报错跳过 |
| 文件处理 | 扫描文件数量上限 | 留空或 0 = 不限制。超限停止收集并给扫描警告 |
| 文件类型 | 待删除扩展名 | 默认 `.log, .moaptindexes`；逗号/分号/空白分隔 |
| 文件类型 | 主程序扩展名 | 默认 `.mpf`；可加其他文本程序扩展名 |
| 文件类型 | 输出扩展名 | 默认 `.MPF`；重命名后的主程序扩展名（保留原大小写） |
| 目录与存储 | APTSOURCE 归档子目录 | 默认 `aptsource`；仅"保存 APTSOURCE"开启时使用 |
| 目录与存储 | 处理前询问备份 | 默认开启；建议保持 |
| 目录与存储 | 配置保存位置 | registry（注册表）/appdata（%APPDATA%）/home（用户目录）；按"存在性检测"选择当前后端，切换后写入并清理另两处残留 |

### 9.2 校验规则页

| 分组 | 设置项 | 说明与操作 |
|---|---|---|
| 基础检查 | 要求程序结束标记（%/M30/M02） | 默认开启 |
| 基础检查 | 要求刀具调用包含 M06 | 默认关闭 |
| 基础检查 | 要求切削前有 S 转速 | 默认关闭 |
| 工艺校验 | G00 级别 | error/warning/allow，默认 error |
| 工艺校验 | 必填 MSG 字段 | 编制/审核/图号/版次 四个开关（默认全开）；程序名/机床/控制系统固定必填不可关 |
| 工艺校验 | M03 补写位置 | after-s（S 所在块尾，默认）/ standalone（独立行） |
| 工艺校验 | F/S 上下限 | F 20~10000、S 500~12000（默认）；留空 = 不检查对应方向。是安全边界，不是"合法档位" |
| F 离群与 S 警告 | F 离群说明 | 抬刀平面分段对比，容差固定 30%（罕见 ≤2 次 + 与其他段差距），**不可通过设置消除** |
| F 离群与 S 警告 | 多 S 值警告 | 默认开启：正文出现多个不同 S 值出警告 |
| 输出格式 | 换行策略 | auto（跟随源文件，默认）/ crlf / lf |
| 输出格式 | 辅助指令顺序 | M03 先于切削、M05 先于结束、M08 先于切削、M09 先于结束（默认全开） |

排故：

| 现象 | 处理 |
|---|---|
| 设置后不生效 | 确认点"确定"保存；点"取消"会回滚。保存后程序自动重新扫描 |
| F/S 上限填了还报越界 | 上限/下限同时生效；确认填写方向正确；留空表示不检查该侧 |
| "恢复默认"把自定义项清掉了 | 恢复默认会回到出厂值并清理注册表/appdata/home 三处残留，自定义刀具类型（special_tools.json）不受影响 |

## 10. 自动改写与校验口径

### 10.1 M03

默认在首个有效 S 程序段补写 M03（after-s）；也可独立成行（standalone）。正文已有 M04 时不补写（正反转冲突报错）；同段 M03/M04、M03/M05、M08/M09 互斥报错。

### 10.2 自动换刀

仅适用于单刀程序：程序已有正确独立 TnM6 时不修改；已有但不正确（T 号不对/缺 M6）在原行修正；无独立换刀指令时在正文首行插入 TnM6。多刀程序或多 T 引用时跳过并提示原因。

### 10.3 覆盖字段

"覆盖已有非空 MSG 字段"只覆盖可编辑字段；机床、控制系统受保护（已有非空值保留）。PROGRAM 随程序名同步；DATE 在确有改动时更新。

### 10.4 注释

括号注释与分号后的内容不参与指令识别。**不要把需要执行的 G/M/F/S/T 指令写在注释中**。

## 11. F 离群检测（结果怎么读）

程序以抬刀平面（程序自身重复出现的最高 Z 面）为界切分为多个"来回"段：下刀 → 加工 → 回到抬刀平面为一段。段内连续加工，F 应一致；段间才是换工序的合法分界。

- **离群告警**（警告）：某 F 全程序显式出现 ≤2 次，且与其他段所有 F 的相对差距都 >60%（如多打一个 0 的 F15000）；
- **复核提示**（info）：差距在 30%~60% 之间，可能合法（单次工艺进给）也可能误输，必须人工确认；
- **轴向豁免**：罕见值全部出现在抬刀平面以下的纯 Z 下刀/钻入行（无 X/Y），且通过「越深越慢」「同深同速」一致性校验时，视为合法切入，不提示；
- **单段程序**：与同目录其它程序常见档位（≥2 个程序使用）对比；无参照时只输出 F 分布表（值×次数×首次行号），不自动判定；
- **APT 参考**：仅辅助上下文（FEDRAT ±10%）。在 APT 内不代表正确，不在也不代表错误；无配对 APT 显示"无 APT 参考"。

排故：

| 现象 | 处理 |
|---|---|
| F 告警很多 | 先分清硬边界（F0/越界）、离群告警、复核提示。检查原始行、其他段的值、最小差距 |
| 能不能关掉 F 离群检查 | 不能通过设置关闭或固定白名单消除——这是设计（防止把异常档位当合法）。单段程序的分布表提示不代表错误 |
| APT 里有这个 F 为什么还提示 | APT 是辅助证据。该 F 在当前 NC 中罕见且远离其他段仍会提示（可能是档位用错工序段） |

## 12. 报告导出与查看

1. 执行"确认并执行处理"；
2. 点击"导出报告"——自动保存到 `NCodeProcessData\ncodeprocess-report-<时间>.json`（保留最新三份），弹窗显示路径；
3. 用 NCodeProcessReportViewer 打开查看（见配套查看器手册）。

报告内容包括：处理汇总与运行环境、每文件动作/目标/状态/失败原因/问题/差异、处理后 MSG 头部快照、换刀跳过原因、重复裁决关系、参数统计、APT 规划与轨迹、F 分段与离群证据、实际配置快照、用户确认与扫描警告、完整内嵌运行日志。程序**不再生成独立日志文件**。

## 13. CLI 使用

预览：

```powershell
python -m ncodeprocess -i "C:\NC-DEMO\JOB-001"
```

执行：

```powershell
python -m ncodeprocess -i "C:\NC-DEMO\JOB-001" --yes --drawing-number DEMO-001 --part-version A
```

导出 JSON：

```powershell
python -m ncodeprocess -i "C:\NC-DEMO\JOB-001" --yes --drawing-number DEMO-001 --part-version A --json-report "C:\NC-DEMO\report.json"
```

不带 `--yes` 永远只预览。校验与处理策略参数与 GUI 设置一致（未显式传参的项读取持久化偏好）。使用 `python -m ncodeprocess --help` 查看完整选项。

## 14. 安全建议

1. 首次处理新后处理格式时使用副本；
2. 处理正式目录前建议先备份（询问备份默认开启）；
3. 校验列为红色（error）的程序应修正后再处理；
4. 从可信渠道获取 EXE，用发布包内 `SHA256SUMS.txt` 核对；
5. 发布构建使用随机字节码加密密钥，同一源码的不同 EXE 哈希不同是正常现象，不要用"与上一版 EXE 字节完全相同"判断构建真伪。
