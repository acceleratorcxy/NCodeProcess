# NCodeProcess 技术文档

> 适用版本：当前 `master`/功能分支代码，程序版本 1.0.0。  
> 公开范围：本文可上传 GitHub；示例路径均为通用占位符，不记录开发机目录、账号、邮箱或代理。  
> 权威性：需求、实现约束、报告契约、已知限制和未完成事项以本文为准；用户操作以《用户手册》为准。

## 1. 项目定位

NCodeProcess 是面向 CATIA 后处理目录的 Windows 便携工具。它扫描 MPF、APTSOURCE 和可清理的中间文件，建立只读预览计划，经用户确认后执行文件改写、重命名、归档或删除，并可导出单个 JSON 审计报告。

核心目标：

1. 在写盘前展示文件动作、头部变化、刀具、参数和校验问题。
2. 保留源文件编码及换行风格，使用临时文件原子替换，失败时不留下半写文件。
3. GUI 与 CLI 共用同一处理链，不维护两套业务规则。
4. 支持 Windows 7，运行时只依赖 Python 3.8 标准库。
5. F 异常检测从当前程序的重复运动结构中学习，不把某组 F 数值当成全局合法白名单。

```text
NCodeProcess/
├─ NCodeProcess.pyw              GUI 开发入口
├─ launcher.pyw                  打包入口
├─ ncodeprocess/
│  ├─ core.py                    数据模型、扫描、计划、校验、报告、执行
│  ├─ gui.py                     Tkinter 界面与线程协调
│  ├─ cli.py                     命令行入口
│  ├─ preferences.py             设置持久化
│  └─ __main__.py                python -m ncodeprocess
├─ tests/                        unittest 测试
├─ docs/                         四份权威文档
├─ build_portable.ps1            Windows 便携构建
├─ NCodeProcess.spec             PyInstaller 规格
└─ run_tests.ps1                 主工具与查看器联合测试
```

`core.py` 不导入 Tkinter。统一业务链为：

```text
scan_directory → build_plan → process_plan
```

GUI 工作线程只能做纯计算或文件 I/O；Tk 控件刷新必须回到主线程并经 `_safe_after` 调度。扫描代际计数器用于丢弃过期结果，扫描期间禁止与“全部应用/应用所选”并发修改同一计划。

## 3. 输入、识别与输出

### 3.1 输入识别

- 主程序扩展名默认 `.mpf`，可配置多个扩展名。
- APT 源文件扩展名为 `.aptsource`。
- 默认清理扩展名为 `.log`、`.moaptindexes`。
- 未知扩展名完全忽略。
- 递归扫描时，任意深度的 `aptsource`、`NCodeProcessData` 及兼容旧数据目录均跳过，防止重复处理归档和报告。
- `max_file_size=0`、`max_files=0` 表示不限制；超大主程序报告错误并跳过，超过数量上限时停止继续收集并给出扫描警告。

### 3.2 程序名来源

程序名按可用信息提取并在报告中记录来源：

1. MPF 头部 `MSG("PROGRAM=...")`；
2. APT 的 `PPRINT PROGNAME ...`；
3. 文件名；
4. GUI 中人工确认或修改。

默认允许中文、英文字母、数字、下划线和连字符。目标扩展名默认 `.MPF`。重名目标先进行裁决或提示，未经覆盖确认不得静默覆盖。

### 3.3 文件动作

- MPF：保留、改写、重命名或因错误跳过。
- APTSOURCE：默认在执行确认后删除；启用“保存 APTSOURCE”时归档到 `aptsource/<时间戳>/`。
- LOG/MOAPTIndexes：列入待删除清单，只有确认清理后执行。
- 未知文件：不移动、不删除、不写入报告处理清单。

输出目录缺省为输入目录，也可由 CLI 指定独立目录。处理前可创建备份；只读目录、无法建立备份或无法原子替换时停止相应写操作。

| `FilePlan` | 单文件来源、目标、动作、原文、输出、问题、差异、APT 与 F 识别数据 |

| `FeedOutlierData` | F episode、结构组、覆盖率、离群、硬边界和上下文复核证据 |

## 5. 头部与正文处理规则

### 5.1 MSG 头部

头部字段顺序固定为：

```text
BIANZHI
SHENHE
PROGRAM
DRAWING NUMBER
PART VERSION
NC MACHINE
CONTROL SYSTEM
DATE
Tn 刀具信息
```

- 图号与版次是执行修改前的 GUI/CLI 必填项。
- 必填 MSG 字段可配置；PROGRAM、NC MACHINE、CONTROL SYSTEM 在界面中保持必要约束。
- PROGRAM 随人工程序名修改同步目标文件名和头部。
- 已有非空 NC MACHINE、CONTROL SYSTEM 不被普通覆盖操作替换。
- DATE 在程序确有改动时更新；无改动时保留。存在匹配 APT 时可采用 APT 生成时间。
- 替换 MSG 时保留原缩进；插入时沿用已有 MSG 的缩进风格。
- HASS 程序的首行 `%` 保留在首行，头部与第一条正文之间不额外插入空行。

### 5.2 M03 与换刀

- 默认自动补写 M03，位置策略为 `after-s`；也可选择 `standalone`。
- 正文已有 M04 时禁止自动补写 M03，并报告主轴方向错误。
- 同段 M03/M04、M03/M05、M08/M09 互斥时报告错误。
- 自动换刀仅适用于单刀且可确认刀号的程序；检测到多刀列表或多个 T 引用时跳过改写并给出警告。
- `require_m06` 开启时，正文存在刀具调用但无有效 M06 会报错；注释中的 M06 不计入。

### 5.3 注释、编码与换行

- 括号注释及分号后的内容不参与指令识别；分号本身保留为程序段终止符。
- 自动编码按 UTF-8 BOM、UTF-8、GB18030 等顺序识别；包含 NUL 字节的疑似二进制/UTF-16 文件拒绝处理。
- `newline=auto` 保留源文件 CRLF/LF；也可强制 `crlf` 或 `lf`。
- 仅换行符不同不视为正文内容变化。

## 6. 校验体系

问题级别为 `error`、`warning`、`info`。错误通常阻止该 MPF 写入；警告和提示用于人工复核。

主要检查包括：

- 必填 MSG、PROGRAM 一致性、正文刀号与头部刀具一致性；
- 未闭合引号、控制字符、缺数值地址、负参数；
- N 号非递增或重复；
- G00/G0 级别（error/warning/allow）；
- 同段冲突运动 G 指令；
- 结束标记 `%`、M30 或 M02；
- M03、M06、S 转速存在性；
- M03/M05/M08/M09 的可选顺序规则；
- F/S 可配置上下限；
- 多个不同 S 值警告；
- APT 与 MPF 的主轴、F/S、刀具、冷却、装夹、程序名和日期交叉校验；
- F 事件级结构离群与上下文复核。

## 7. F 异常检测

### 7.1 原则

核心统计不使用固定合法 F 表。一个数值即使常见，也不能仅凭“属于传统档位”跳过结构复核；一个数值即使很少见，在没有程序内重复结构参照时也不会仅凭绝对大小被判离群。

硬边界独立存在：F0、负值以及配置的 `feed_min/feed_max` 越界直接按错误处理。这些是用户配置的安全边界，不是统计合法档位。

### 7.2 Episode

- 每个显式 F 开启一个 episode，直到下一显式 F 或程序结束。
- 模态继承行只用于补充该 episode 的运动结构，不增加样本权重。
- F-only 设定行可以建立 episode，但没有运动事实时会降低结构可比性。
- episode 记录行号、原值、运动轴、运动族、Z 趋势、退刀平面状态、阶段角色和转阶段证据。

### 7.3 阶段角色

阶段由 Z 方向、XY 运动、G00/运动族、退刀平面和前后 episode 关系确定，F 数值不参与阶段命名：

```text
进刀：move-in → plunge → approach → cut
退刀：cut → retreat-near → retreat-clear → move-out
```

- `move-in/move-out`：安全高度定位或离开。
- `plunge`：主体下探。
- `approach`：切削前最后接近。
- `cut`：加工区域运动。
- `retreat-near`：切削后慢速离面。
- `retreat-clear`：离开表面后、进入安全移动前的受控退刀。
- 无法确认时为 `transition-uncertain`，不强行建立可靠参照。

进刀和退刀允许复用速度：`retreat-near` 可以采用 approach 速度，`retreat-clear` 可以采用 plunge 或 move 速度；是否异常仍取决于同阶段结构的重复证据。

### 7.4 结构组与判定

结构签名包含轴类别、运动族、Z 趋势、退刀状态和阶段角色，不包含 F 值或绝对 Z 距离。

1. 先建立精确 `peer_groups`。
2. 精确组不足时，只按结构规则建立同角色 `compatible_peer_groups`。
3. 默认至少 3 个独立 episode 使用同一 F 才形成重复参照。
4. 稳定组中候选 F 若只出现少量、在全程序及粗粒度相关结构中也没有重复支持，并同时超过倍率或低/高侧容差，生成 `feed-outlier`。
5. 精确组产生高/中置信度；兼容组只能产生中置信度。
6. 普通唯一结构只进入覆盖率，不逐条显示“结构样本不足”。只有多峰冲突且存在可疑候选、又无法形成稳定参照时，才生成一条组级 `insufficient_evidence` 汇总。

当前参数：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `feed_outlier_min_count` | 3 | 同一结构中形成重复参照的最少 episode 数 |
| `feed_outlier_ratio` | 2.0 | 候选与参照的相对倍率阈值，按 `log(F)` 距离解释 |
| `feed_outlier_low_ratio` | 0.8 | 参照低侧容差，不是全局 F 下限 |
| `feed_outlier_high_ratio` | 1.2 | 参照高侧容差，不是全局 F 上限 |
| `retract_z_threshold` | 20.0 | 无 APT 退刀平面时的默认 Z 参考 |

APT `FEDRAT` 仅作为 `in_apt` 上下文和交叉校验参考，既不是全局白名单，也不覆盖核心结构离群结果。

### 7.5 输出与兼容字段

`feed_outlier` 保留旧版汇总字段以兼容查看器，同时以新字段为主要证据：

- `episodes`：阶段与运动证据；
- `peer_groups`、`compatible_peer_groups`：结构组计数和常见参照；
- `phase_common_feeds`：阶段级汇总；
- `coverage`：总 episode、已比较、未比较、冲突证据组；
- `outliers`：行号、F、原因、APT 状态、结构组、样本数、置信度和详细证据；
- `insufficient_evidence`：组级冲突摘要；
- `boundary_errors`：硬边界；
- `context_reviews`：非阻断人工复核。

旧字段 `common_feeds`、`stage_common_feeds`、`envelope` 只用于向后兼容和诊断，不应解释为固定合法值表。

## 8. APT 解析与交叉校验

程序只为每个 MPF 选择最新的配对 APTSOURCE，并提取：

- 机床、后处理表、CATIA APT 版本、生成时间、程序名；
- 操作列表及操作级主轴/进给；
- 冷却液、装夹刀具、刀具规格；
- GOTO 点数、XYZ 行程、圆弧数、抬刀次数和推导退刀平面。

交叉校验口径：

- 主轴方向不一致：error；
- S 允许约 ±1%、F 允许约 ±10%；
- 刀具直径允许约 ±2%、圆角允许约 ±5%；
- 参数、刀具几何或程序名不一致：warning；
- 冷却、装夹顺序、DATE 过期：info。

APT 缺失或无法解析时，MPF 仍按自身规则处理；APT 识别失败应记录问题和运行日志，不得导致整个目录崩溃。

### 9.2 保存位置

设置按“存在性检测”定位：

1. 当前用户注册表 `HKCU\Software\NCodeProcess`；
2. `%APPDATA%\NCodeProcess\settings.json`；
3. 用户主目录下 `settings.json`。

哪个位置先检测到已有配置，哪个位置就是当前保存后端，不跨后端合并。用户显式切换后端时，写入完整设置并清理另两处残留。旧 `HKCU\Software\NCPostProcess` 仅用于兼容读取历史编制/审核值。

## 10. GUI 与 CLI

### 10.1 GUI

GUI 启动后扫描程序所在目录。主界面包含文件计划、程序信息、刀具编辑、MSG 预览、识别数据、参数统计、校验问题和差异预览。所有写盘动作都位于最终确认之后。

“全部应用”在后台重新计算所有 MPF，并用代际标记防止旧结果覆盖新扫描；“应用所选”只重新计算当前文件。二者都只更新预览，不等于执行写盘。

### 10.2 CLI

基本形式：

```powershell
python -m ncodeprocess -i "<输入目录>"
python -m ncodeprocess -i "<输入目录>" --yes --drawing-number DEMO-001 --part-version A
```

不带 `--yes` 只预览。主要选项包括输入/输出、递归、覆盖、APTSOURCE 保存、头部字段、刀具、编码、M03/换行、F/S 边界、辅助顺序、F 结构检测参数、文件上限、退刀阈值以及 JSON/CSV 报告路径。显式 CLI 参数优先；未显式提供的校验设置读取与 GUI 相同的持久化偏好。

## 11. 报告数据契约

### 11.1 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `input_dir/output_dir` | string | 输入和输出目录 |
| `started_at/finished_at` | string | 开始/结束时间 |
| `success/failed/skipped/moved/deleted` | integer | 执行动作计数 |
| `warnings/errors` | integer | warning/error 总数 |
| `files` | array | 文件明细 |
| `backup_dir` | string | 本次备份目录，未备份为空 |
| `runtime_log` | array | 完整内嵌运行事件 |
| `log_path` | string | 兼容字段，当前恒为空 |
| `app_version` | string | 生成工具版本 |
| `report_schema_version` | integer | 当前为 1 |
| `config_snapshot` | object | 本次实际配置快照 |
| `user_confirmations` | array | 用户确认记录 |
| `scan_warnings` | array | 扫描期警告 |
| `archive_stamp` | string | 归档时间戳 |
| `elapsed_seconds` | number | 处理耗时 |
| `generator` | string | `gui` 或 `cli` |
| `apt_summary` | object | APT 全局摘要 |

### 11.2 `files[]`

每项包含：`file`、`action`、`program`、`encoding`、`target`、`program_name_source`、`changes`、`diff`、`issues`、`stats`、`apt_meta`、`toolpath_stats`、`feed_outlier`，执行后还包含 `status` 或失败信息。

`issues[]` 固定字段为 `filename`、`line`、`text`、`kind`、`severity`、`suggestion`。新增 kind 时必须同时更新主工具展示、查看器兼容逻辑、测试和本文。

### 11.3 日志与导出

运行日志是最多 500 条的内存环形缓冲，字段为 `time/level/event/message/detail`。程序不自动生成磁盘日志；导出 JSON 时把快照完整写入 `runtime_log`，`log_path` 恒为空。

GUI 导出到程序目录的 `NCodeProcessData`，默认只保留最新三份 `ncodeprocess-report-*.json`。CLI 只有显式传入 `--json-report` 才生成 JSON；`--csv-report` 另导出问题清单，不改变 JSON 契约。

## 12. 兼容、构建与安全

- 语法限定 Python 3.8，不使用 3.9+ 特性。
- 最低完整界面目标为 Windows 7、1366×768、100% DPI；更低分辨率只保证基本可操作。
- 便携包不创建安装项、服务、启动项或文件关联。
- 发布构建使用 PyInstaller `-OO`、临时随机 16 位 PYZ 密钥、随机 hash seed、运行时加固 hook、模块排除和 SHA-256 清单。
- `tools/upx/upx.exe` 存在时自动启用 UPX；缺失时仍可构建。
- 每次随机密钥与 hash seed 不同，因此 EXE 不可逐字节复现，发布完整性以同一包内 `SHA256SUMS.txt` 为准。
- Authenticode 仅在构建时显式提供证书指纹后启用。

## 13. 测试约束

- 使用标准库 `unittest`，功能改动遵循 RED → GREEN → 全量回归。
- `test_core.py` 覆盖纯逻辑，`test_gui.py` 覆盖布局与线程生命周期，`test_cli.py` 覆盖命令行，`test_preferences.py` 覆盖三后端设置，`test_release_assets.py` 覆盖发布元数据。
- GUI 测试使用独立注册表键；设置文件测试把 AppData 和用户目录替换为临时目录。
- 用例数量以 discover 实际输出为准，不作为固定验收常量。
- 测试和打包必须在真实 Windows/Python 3.8 环境完成；受限沙箱中的结果不能替代发布验收。
