## 一、关于这个程序的详细理解

### 1. 程序定位

**NCodeProcess** 是一个 CATIA 后处理 NC 程序批量整理工具，目标平台为 Windows 7（必须兼容）及后续 Windows 版本，交付形态为免安装便携式 EXE（PyInstaller 单文件、AES 加密 PYZ）。

后处理通常会生成多类文件：`MPF`（数控主程序，交付核心）、`aptsource`（APT 源文件，是否留档由用户决定，默认删除）、`LOG` / `MOAPTIndexes`（中间文件，默认清理）。不同后处理（V5-2500B、HASS）生成的 MPF 头部格式不同：HASS 通常缺少程序信息需自动补写，V5-2500B 常缺 `M03`。工具在 EXE 所在目录自动完成：批量整理文件 → 规范程序名 → 补全程序头部（编制/审核/图号/版次/机床/控制系统/日期/刀具）→ 检查并自动补写 M03 → 校验 NC 指令 → 输出参数统计与处理报告。

### 2. 架构分层

```
NCodeProcess/
├─ ncodeprocess/
│  ├─ __init__.py      # 版本号
│  ├─ core.py          # 纯逻辑层：模型、扫描、计划、处理、校验、统计（无 GUI 依赖）
│  ├─ gui.py           # Tkinter 界面层（表格、表单、编辑/对比窗口、悬停提示）
│  ├─ cli.py           # 命令行入口（--input/--output/--yes 等）
│  ├─ preferences.py   # Windows 注册表读写（保存编制/审核）
│  └─ __main__.py      # 入口
├─ launcher.pyw        # PyInstaller 打包入口，启动 GUI
├─ NCodeProcess.spec   # PyInstaller 规格（加密键、版本资源、排除项）
├─ build_portable.ps1  # 便携打包脚本（临时 AES 键、SHA256SUMS、zip）
├─ tests/              # test_core.py / test_gui.py / test_release_assets.py
└─ docs/               # 需求逻辑审查报告、设计审查报告、本记录
```

设计上 `core.py` 与 GUI 解耦：全部处理逻辑可被 CLI 与 GUI 复用，GUI 只负责展示与交互。

### 3. 核心数据模型（core.py）

| 模型 | 作用 |
|---|---|
| `Config` | 处理配置：递归、编码（auto/utf-8/gb18030）、M03 自动补写、自动换刀、G00 级别（error/warning/allow）、删除扩展名、数据目录名等 |
| `ProgramInfo` | 编制/审核/图号/版次/机床/控制系统/日期/刀具；`fields(program)` 生成 MSG 头字段字典 |
| `ToolInfo` | 刀具号 + DIA/TOOL_CONER/TOOL_ANGLE/TOOL_TYPE，数值规范化为 3 位小数；`to_msg()` 生成 `T1:DIA=...` 格式 |
| `FilePlan` | 单文件处理计划：来源、类型（mpf/aptsource）、程序名、目标、动作、校验问题、原始/输出文本、统计、修改说明 |
| `Issue` | 校验问题：文件名、行号、类型、级别（error/warning/info）、原文、建议 |
| `Stats` | F/S/X/Y/Z 计数、最小值、最大值，以及 G00 快速定位次数 |
| `ScanResult` | 扫描结果：文件列表 + 警告 |
| `ProcessReport` | 处理报告，支持 JSON/CSV 导出与时间戳存档 |

### 4. 处理流水线

```
scan_directory(目录, Config)
   → build_plan(scan, ProgramInfo, Config)
       program_defaults   → 头部默认值（HASS 需要时）
       apply_header       → 写/补 MSG 头（replace_tools=True 时重写刀具）
       add_initial_tool_change → 自动添加首换刀 TnM6 并统一刀具号
       add_m03            → 检查正文 M03，缺失时在首个 S 指令后补写（S 检测已排除注释）
       analyze_program    → 语法/合理性校验 + 参数统计
   → GUI/CLI 预览
   → process_plan         → 执行写入/移动/删除
   → save_timestamped_report / write_json / write_csv
```

校验规则要点：`validate_program` 检查头部完整性、行号 N 规律、G00 快速定位（级别可配）、缺 M30/M02 结尾、控制字符、非法地址、换刀与 M06 关系等；**自动补写 M03 失败时（正文找不到可插入位置），spindle-start 类问题升级为 error**（原为 warning，按需求 FR-05.6 修正）。

### 5. GUI 结构与交互（1290×720，Win7 兼容）

- **顶部**：自动扫描目录区、程序信息表单（编制/审核/图号/版次/日期）、选项（覆盖已有 MSG 字段 / 自动补写 M03 / 自动添加换刀指令）、G00 级别。
- **左侧 Notebook**：
  - 「保留 / 归档文件」：保留表（动作/程序名/MPF 源文件/目标）+ 窄校验列（`0 错 / 0 警`，错误红字）；支持**多选**，右键菜单提供「编辑程序代码」「对比所选两条程序」（对比**有且只有 2 条**选中才可用）。
  - 「APTSOURCE 文件」「待删除文件」：分别展示归档/删除计划。
- **右侧 Notebook**：解析信息、校验问题、参数统计、修改差异（修改前/后红绿高亮）。下方为「当前程序刀具信息」可编辑表格。
- **手动编辑程序代码窗口**：双击或右键「编辑程序代码」打开，正文带**行号 gutter**（浅灰底只读栏，随编辑/滚动同步）；保存后调用 `reprocess_file` 在内存中重跑整个流水线并重新审查、刷新预览，不直接写盘。
- **程序差异对比窗口**：左右双栏对齐展示两条程序；**不同部分红色底色、相同部分绿色底色**；**双侧各自独立行号**（各自原始行号编号，无内容侧留空）；**左右滚动完全独立**（内容与自身行号一起滚，互不影响）；窗口标题与两侧面板均显示「文件名（程序名）」，文件名优先。
- **单元格悬停提示**：鼠标停留在单元格上 1.5 秒后，若内容超出列宽（被截断）则在鼠标旁弹出置顶小窗显示完整内容；移出/点击/滚动即隐藏；覆盖 9 张表格（保留表、校验列、APTSOURCE、待删除、解析信息、校验问题、参数统计、刀具表、全部程序参数统计弹窗）。
- **窗口/字体/列宽自适应**：`window_geometry_for_screen` 按屏幕尺寸收缩（1290×720 / 1286×668 分支）；`choose_ui_font_family` 优选微软雅黑等并重配 Tk 字体族；列宽按表头字体实测拟合，保证默认状态无需拖拽即可见全部表头。

### 6. 关键机制

- **保存编制/校对原理**：写入 Windows 注册表 `HKCU\Software\NCodeProcess`（值 `bianzhi`/`shenhe`，REG_SZ），启动时读取；兼容旧键 `HKCU\Software\NCPostProcess`。非 Windows 平台自动跳过。
- **线程安全**：GUI 中所有界面刷新均通过 `self.after()` 调度回到主线程，避免跨线程直接操作 Tk。
- **打包**：`build_portable.ps1` 每次生成临时 16 位 AES 键注入 PyInstaller 加密 PYZ；产出 `dist\NCodeProcess.exe`、`NCodeProcess-Package\`（含 README/SECURITY/VERSION/SHA256SUMS）、`NCodeProcess-Windows7-Portable.zip`。
